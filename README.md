# MD Previewer for Windows

**紹介ページ: <https://yvvakimoto.github.io/md_previewer/>** ／ **ダウンロード: [最新リリース](https://github.com/yvvakimoto/md_previewer/releases/latest)**

Windows 専用の、軽量なスタンドアロン Markdown プレビューアです。  
インターネット接続不要で動作する **閲覧主眼** のビューアで、GitHub Flavored Markdown に加え、図・数式・スライドなど多彩な拡張記法に対応しています。補助機能として、`E` キーで開く内蔵エディタ（CodeMirror 6 + Vim 対応）も同梱しています。

普段使いのテキストエディタで編集 → 保存で自動再読み込み、あるいは内蔵エディタで編集と保存、どちらのワークフローでもお使いいただけます。

---

## 他の Markdown ビューアとの違い

本ツールの設計上のモチベーションは、次の 2 点です。

1. **エンジニアではないユーザー** でも、`.md` ファイルをダブルクリックするだけで見やすく表示できること
2. **表示方法（CSS）の差し替え・追加が簡単** で、組織やプロジェクトの体裁を 1 枚の CSS で配布できること

代表的な既存ツール（VS Code の Markdown Preview / Obsidian / Typora）と並べた比較を以下に示します。

| 観点 | MD Previewer（本ツール） | VS Code Markdown Preview | Obsidian | Typora |
| --- | --- | --- | --- | --- |
| 想定ユーザー | 非エンジニア含む閲覧者全般 | エンジニア | ノート編集者（個人 KMS 用途） | ライター／ドキュメント作成者 |
| 起動方法 | `.md` をダブルクリック／フォルダ右クリック | 関連付け可。表示は `Ctrl+Shift+V` でプレビューを開く | vault が前提（単体ファイルは扱いにくい） | 関連付けでダブルクリック |
| 編集 vs. 閲覧 | **閲覧が主軸**。編集は内蔵エディタ（`E` キー、Vim・数式入力支援・セルモード） | エディタ主体（プレビューは副次） | エディタ主体 | WYSIWYG エディタ主体 |
| インストール要件 | 管理者権限不要・WebView2 のみ（Windows 標準） | VS Code 本体（数百 MB） | アプリ本体（Electron） | アプリ本体（Electron） |
| オフライン動作 | ◯（CDN 不使用、全アセット同梱） | ◯ | ◯ | ◯ |
| **CSS テーマの追加方法** | **`assets/` に `.css` を 1 枚置くだけ**（`S` キーのモーダルで選択） | `settings.json` の `markdown.styles` に絶対パス／URL を列挙 | コミュニティテーマのインストール／`.obsidian/snippets/` に CSS 配置 | テーマフォルダに `.css` 配置（命名規約あり） |
| ライセンス | OSS（無償） | OSS（無償） | 個人利用無償／商用有償 | **有償**（v1.0 以降ライセンス購入が必要） |
| 拡張記法 | Mermaid / KaTeX / Marp スライド / CSV・TSV テーブル / **外部CSV→Plotly 対話的チャート** / ABC 楽譜 / **Markwhen タイムライン／カレンダー**（`display: calendar`・祝日はオンライン時のみ考慮） / **tikz-cd 可換図式**（WASM TeX、描画はオフライン／初回のみ要DL） / **Kataskeve 平面幾何・Kataskeve3D 立体幾何の作図**（陰線処理つきペン画風） / **Feynman 図**（[feynmark](https://github.com/yvvakimoto/feynmark)、宣言的 DSL・自動レイアウト） / Footnote ツールチップ（標準同梱） | 多くは拡張機能の追加導入が必要 | コアおよびプラグインで対応 | Mermaid / KaTeX 等を内蔵（Marp 非対応） |
| 単独 HTML / PDF エクスポート | ◯（`X` キー、自己完結 HTML／しおり・リンク付き PDF を拡張子で選択） | △（拡張機能依存） | △（プラグイン依存） | ◯ |

### 補足

- **VS Code との違い**: VS Code はエンジニア向け統合開発環境であり、Markdown プレビューはあくまでサイドパネル機能です。CSS のカスタマイズは `settings.json` の `markdown.styles` 配列に絶対パスや URL を列挙する必要があり、非エンジニアには敷居が高めです。本ツールは exe をダブルクリックして開き、`assets/` フォルダに `.css` を置くだけでテーマ候補に加わります（詳細は後述の「テーマのカスタマイズ」を参照）。
- **Obsidian との違い**: Obsidian は vault（フォルダ）を前提とした強力なノート編集アプリで、「もらった単一の `.md` をとりあえず見たい」という用途には機能過剰になりがちです。本ツールは単一ファイル / フォルダどちらにも対応しつつ、編集は外部エディタ または `E` キーの内蔵エディタ（保存検知で自動再読み込み）に委ね、閲覧体験に焦点を絞っています。
- **Typora との違い**: Typora は WYSIWYG 編集を主目的とした有償ツールで、`.md` の関連付けはインストーラが行うためダブルクリックで開けます。本ツールは OSS で無償、編集 UI を表に出さない代わりに、Marp スライド・CSV テーブル・Footnote ツールチップ・自己完結 HTML エクスポートなど、**閲覧と配布のシナリオ** に最適化された機能を備えています（詳細は後述の「対応している記法・機能」を参照）。

### 本ツールが特に向くケース

- 他人から受け取った `.md` を、追加セットアップなしで一発で開いて見たい
- 自社・チームのロゴや配色を反映したテーマを **1 枚の CSS** として配布したい
- 社内クローズド／オフライン環境で安心して動かしたい
- レビュー結果を **単独 HTML ファイル** として共有・配布したい

## 配布物の中身

インストール先（`%LOCALAPPDATA%\Programs\MdPreviewer\`）には、以下のファイル／フォルダが展開されます。

| 名前 | 内容 |
| --- | --- |
| `md-previewer.exe` | 実行ファイル本体。スタートメニューから起動するか、`.md` ファイルをダブルクリックして使います。 |
| `assets/` | UI テンプレート、テーマ CSS、Marp テーマ、各種ライブラリ。**必ず `md-previewer.exe` と同じフォルダに置いてください。** |
| `samples/` | 機能デモ用の Markdown 例。スタートメニューの **"Sample Documents"** からも開けます。動作確認や記法のリファレンスとしてご利用ください。任意なので削除しても本体動作には影響しません。 |
| `README.md` | 本書（使い方・機能一覧・ショートカット・カスタマイズ方法）。スタートメニューの **"使い方 (README)"** から、本アプリ自身で開けます。文中の `samples/` へのリンクもそのまま辿れます。 |
| `HISTORY.md` | バージョンごとの更新内容（リリースノート）。インストール直後に自動で開きます。スタートメニューの **"更新履歴 (Release Notes)"** からも開けます。 |

| `md-previewer.log` | 起動するたびに上書きされる診断ログ（不具合報告時に参照）。 |

## インストールと起動

配布されている `MdPreviewer-Setup-<version>.exe` をダブルクリックしてください。

- インストール先は **`%LOCALAPPDATA%\Programs\MdPreviewer\`**（管理者権限不要、ユーザー単位）
- インストール時のチェックボックスで、次を一括で設定できます（既定オン、任意でオフ可）:
  - `.md` / `.markdown` / `.mdx` 拡張子を MD Previewer に関連付け（ダブルクリックで起動）
  - フォルダの右クリックメニューに **"Open with MD Previewer"** を追加
  - `.md` / `.mdx` ファイルの右クリックメニューに **"Open with MD Previewer"** を追加
- インストール完了画面では既定で **更新内容（`HISTORY.md`）を表示して MD Previewer を起動** します。表示が不要な場合はそのチェックを外してください。同じ画面のチェックボックスから **使い方（本 `README.md`）** を開くこともできます。
- スタートメニューには **"使い方 (README)"** / **"更新履歴 (Release Notes)"** / **"Sample Documents"** / **"Third-party Licenses"** のショートカットが作られます。使い方と更新履歴は MD Previewer 自身で表示されます。
- アンインストールは **Windows「設定 → アプリ」** から行えます（同インストーラが書き込んだ設定も自動で削除されます）

起動後のウィンドウへ `.md` ファイルやフォルダをドラッグ＆ドロップすると、その内容が表示されます。コマンドラインから直接渡すこともできます。

```bat
md-previewer.exe path\to\file.md
md-previewer.exe path\to\folder
```

> Windows「設定 → 既定のアプリ」で `.md` の既定として別アプリを明示的に選んでいる場合、その選択がインストーラの関連付けより優先されます。その際は「設定」から既定を切り替えるか、右クリックメニューの **"Open with MD Previewer"** をお使いください。

## ワークスペース（フォルダ）モード

フォルダパスを渡すと、その中のすべての `.md` を一覧表示する **ワークスペースモード** に切り替わります。

```bat
md-previewer.exe path\to\folder
```

- フォルダをウィンドウへドラッグ＆ドロップしても起動できます。
- サイドバーに **ファイルツリー** が現れ、フォルダ単位で折りたたみ可能です。クリックすると当該ファイルが読み込まれます。
- ファイル順は次の優先順で決まります：
  1. `_toc.md`（フォルダ直下）— ネストした箇条書きで明示的に指定
  2. `_toc.md` が無ければ ABC 順（ディレクトリ → ファイルの順、ドットファイルや `node_modules` 等は除外）
- `_toc.md` に書かれていない `.md` は末尾の **Other** グループに自動で並びます。
- ファイルツリーを **右クリック**すると **「すべて閉じる」／「すべて開く」** で、フォルダと各ファイルの見出しをまとめて折りたたみ／展開できます（開閉状態は次回起動時にも復元されます）。

### `_toc.md` の書式

```markdown
- [はじめに](intro.md)
- 章
    - [入門](chapters/01-getting-started.md)
    - [応用](chapters/02-advanced.md)
- [おわりに](conclusion.md)
```

リンクは Markdown 標準の `[タイトル](相対パス.md)`。ネストしたリストは折りたたみ可能なグループになります。

### ワークスペースの HTML エクスポート

ワークスペースモードで `X` キーを押すと、出力先フォルダ選択ダイアログが開きます。  
中身のすべての `.md` を `.html` に変換し、元のディレクトリ構成を保ったまま書き出します。各ページにはファイルツリーが付くので、静的サイトとしてそのままホスティングできます。

> `X` キーは単一ファイル表示時には単独 HTML ファイル出力、ワークスペースモード時にはフォルダ一括出力、と挙動が自動で切り替わります。

## `.mdx` バンドル形式

`.mdx` は、**Markdown 本体（`index.md` または `README.md`）と、そこから参照される画像・CSV・動画などの資源を 1 つの ZIP にまとめた単一ファイル**です。資源がバラバラにならず、1 ファイルで配布・受け渡しできます。

- **開く**: `.md` と同じく、ダブルクリック／ドラッグ＆ドロップ／コマンドライン／関連付けで開けます。ZIP は一時ディレクトリに展開され、中の `index.md`（無ければ `README.md`、それも無く `.md` が 1 つだけならそれ）がエントリとして表示されます。画像・CSV などの相対パスはそのまま解決されます。
- **編集して保存**: `E` キーの内蔵エディタや Marp テーマ変更で本文を保存すると、変更は**元の `.mdx` に自動で再パッキング**されて永続化されます。
- 中身は通常の ZIP なので、エクスプローラで拡張子を `.zip` に変えれば中身を確認・編集することもできます。

サンプル: `samples/bundle.mdx`

```bat
md-previewer.exe path\to\bundle.mdx
```

## 自動更新（社内配布向け・既定オフ）

社内ネットワーク完結で、**起動時に最新版を確認 → 新しければバナー通知 → 承認でバックグラウンド更新**するオプション機能です。

- **既定は完全オフ**。通常のビルドは設定ファイルを同梱しないため、この機能は一切動かず、**アプリは従来どおり完全オフラインで動作**します。
- 設定ファイル `update.json`（exe と同じ場所、または `assets/` 内）が存在し `enabled: true` のときだけ有効になります。更新元は**社内ファイル共有（UNC パス `\\サーバ\共有\...`）**で、外部インターネットへはアクセスしません。
- 新版検出時は **画面右下に小さな通知カード**（本文を隠さない控えめな表示）が出て、**「今すぐ更新」／「終了後に更新」／「×」（閉じる）／「今後表示しない」** を選べます。
  - **今すぐ更新** — アプリ終了 → サイレント更新（管理者権限不要）→ **自動再起動**（開いていた文書も開き直します）。
  - **終了後に更新** — 更新を**予約するだけ**でその場は何も起きないので、読みかけ・書きかけの作業をそのまま続けられます。自分でアプリを閉じたときに静かに更新が実行され、**次に起動したときから新しいバージョン**になります（再起動はしません）。予約はそのとき限りなので、更新せずに閉じてしまった場合は次回起動時にまたカードが出ます。
  - **×** — 今回だけ閉じます（次回起動時にまた出ます）。**今後表示しない** — その端末では以後カードを出しません。
- 有効化するには、配布元が `assets/update.json` を用意して共有フォルダを指す設定を書きます（設定例は `assets/update.example.json`）。手順の詳細は組織の配布パッケージ側のドキュメントを参照してください。

## 対応している記法・機能

- **GitHub Flavored Markdown** — 表、タスクリスト、打ち消し線、自動リンクなど。タスクリスト（`- [ ]` / `- [x]`）は通常プレビューだけでなく **Marp スライドでも** チェックボックスとして表示されます
- **改行連結（ソフト改行の連続化）** — ソース上で 1 つの改行で折り返した文を、1 つの連続した文として表示。和文（CJK）どうしの改行はスペースを入れずに詰めて連結し、英文は半角スペースで連結。行末に半角スペース 2 つ（または `\`）を置いた明示的な改行はそのまま維持。[改行連結のサンプル](samples/softbreak.md) 参照
- **シンタックスハイライト** — `highlight.js` による多言語対応、コードブロック右上にコピーボタン。highlight.js 本体が文法を持たない **Modelica**（` ```modelica `、別名 `mo` / `mos`）にも対応（自作の文法定義 `assets/libs/hljs-modelica.js` を同梱）。[シンタックスハイライトのサンプル](samples/syntax.md) 参照
- **Mermaid 図** — フローチャート、シーケンス図、ガントチャート ほか
- **KaTeX 数式** — インライン `$...$`、ブロック `$$...$$`。数式を **右クリック**すると **「Copy MathML」/「Copy LaTeX」** のメニューが出て、Word などへ貼れる MathML と元の LaTeX ソースをコピーできます（通常プレビュー・Marp スライドの両方）。数式以外を右クリックしたときは従来どおりブラウザ標準のメニュー（戻る／進む）が出ます
- **脚注** — `[^id]` 参照と `[^id]: 本文` 定義。本文末尾に脚注一覧、参照部はマウスオーバーで Wikipedia 風ポップアップ表示
- **定義リスト（用語集）** — 用語を 1 行で書き、次の行を `: ` で始めると `<dl>` として描画（Pandoc / PHP Markdown Extra 互換）。`: ` の行を続ければ 1 用語に複数の説明、連続する組は 1 つのリストにまとまります。用語と説明の間に空行を挟む loose 形式にも対応。説明を 2 スペース以上字下げすれば段落・箇条書き・コードブロック・画像も置けます。**通常プレビューと Marp スライドの両方**で使え、HTML / PDF エクスポートにも追従。見た目は CSS 変数 `--md-dl-*` でテーマ側から上書き可能。[定義リストのサンプル](samples/deflist.md) 参照
- **テキスト配置（センタリング・右寄せ）** — `::: center` / `::: right` / `::: left` … `:::` で囲んだブロック（見出し・段落・「記」「以上」など）を中央寄せ・右寄せ・左寄せ。引用ブロック内で `> -- 著者名` のように `--`/`—`（em ダッシュ）で始まる行は出典として自動右寄せ。縦書きテーマ（tategaki）では行末＝列の下端に写像。[配置のサンプル](samples/alignment.md) 参照
- **中央揃え強調メッセージ** — `::: message` … `:::` で囲むと、中央寄せ＋大きな太字＋上下のアクセント罫でメッセージを強調表示。Marp スライドで結論やキーメッセージを読みやすく提示したいときに便利（配置だけの `::: center` と異なり視覚的に強調）。アクセント色は CSS 変数 `--md-message-*` で Marp テーマ／ユーザースタイル側から上書き可能。[配置のサンプル](samples/alignment.md) 参照
- **上下・左右中央寄せ** — `::: vcenter` … `:::` で囲むと、内容を上下・左右とも中央に配置。主に Marp スライドで効果を発揮し、見出しの下の残りスペースいっぱいを使って図や文を縦横中央に据えます（図 1 枚を中央に置く「センター図スライド」に最適）。通常の Markdown 文書では高さ固定枠が無いため左右中央のみ。はみ出す場合は自動縮小（`A` キー）が本文を縮めるので見出しと重なりません。[配置のサンプル](samples/alignment.md) 参照
- **多段組み（カラム）** — `::: columns` … `+++` … `:::` で囲むと、その範囲だけを複数カラムにできます（前後は全幅の1カラムのまま。`:::` で1カラムへ復帰）。列は内部の `+++` で区切り、`::: columns-3` のように列数の明示も可能（2〜4 列）。**通常の Markdown 文書でも Marp スライドでも使えます。** Marp ではスライド全体を分割する `<!-- _class: split -->` と違い途中の一部だけをカラム化でき、列内に `::: center` も入れ子にできます（入れ子は Marp のみ。通常文書では最初の `:::` で閉じます）。[配置のサンプル](samples/alignment.md) / [Marp のサンプル](samples/marp.md) 参照

- **ルビ（振り仮名）** — 漢字に読み仮名を添えるでんでんマークダウン互換の記法。`｜猫《ねこ》`（バー形）、`漢字《かんじ》`（`｜` を省くと直前の漢字列が親文字）、`{吾輩|わがはい}`（波括弧形）の 3 通りで書けます。読みを `|` で区切ると、区切り数が親文字の字数と一致したときだけ **モノルビ**（1 字ずつに割り当て）になり、合わないときはグループルビへ自動で戻ります。`\｜` `\《` `\》` でエスケープ可能。**通常文書でも Marp スライドでも有効**、HTML / PDF エクスポートにも追従。縦書きテーマ（tategaki / bunko）ではルビが行の右側に出て、`bunko` では 16 行の行取りグリッドを崩さないよう調整済みです。[ルビのサンプル](samples/ruby.md) 参照

| `Home` / `End` | 最初 / 最後のスライドへ（deck モード時） |
| `F` | フルスクリーン切替（deck モード時） |
| `A` | スライドの自動縮小 ON / OFF（はみ出し時、タイトル/ヘッダー/フッターは固定のまま本文だけを縮小して 1 枚に収める。既定 ON。OFF 時や縮小下限超過分は本文をスクロールバーで追える） |
| `Ctrl` + ホイール / ドラッグ | カーソル位置を中心に拡大・縮小 / 拡大中はドラッグで移動（deck モード時） |
| `Z` | レーザーポインタ ON / OFF（deck モード時。マウスに追従する光点と尾を引く軌跡。色は CSS 変数 `--laser-color` で変更可） |

list モードのサムネイルをクリックすると、そのスライドの deck モードに飛びます。deck モードでは `Ctrl` + マウスホイールでカーソル位置を中心にスライドを拡大・縮小でき、拡大中はドラッグで表示位置を移動できます（スライド切替で等倍に戻ります）。

**目次サイドバー**: scroll / list モードでは左に **スライド目次** が表示され、各スライドの見出しを一覧できます。項目をクリックすると、scroll モードではそのスライドへスクロール、list モードでは deck モードに入ってそのスライドへフォーカスします。スクロールに追従して現在のスライドの見出しがハイライトされます。**deck モードではスライドに集中できるよう目次サイドバーは非表示** になります。

## 表示言語（日本語 / English）

UI の文言は日本語と英語を切り替えられる。既定は **OS のロケール自動判定**で、
`ja` 系なら日本語、それ以外は英語になる。明示的に選ぶとその選択が優先される。

- **切り替え**: `H` キーのヘルプモーダルのフッタにある `自動 / 日本語 / English`。
  エディタウィンドウ側は `⚙ 設定` → 「表示」→「表示言語」。
- **即時反映**: 再起動もリロードも不要。プレビューとエディタの両方が同時に切り替わる
  （両ウィンドウは設定を共有している）。
- **既存ユーザー**: これまで日本語で使っていた環境は日本語のまま。自動判定が働くのは
  新規インストールだけなので、英語版 Windows で使っていても勝手に英語にはならない。
- **対象**: アプリの UI 文言のみ。開いている Markdown の中身、`samples/` の文書、
  ファイル名、Marp のテーマ名などは変わらない。
- **HTML / PDF エクスポート**: 書き出した時点の表示言語がそのまま成果物に入る
  （サイドバーの見出しなど）。

同梱テーマ（`bunko.css` / `tategaki.css`）の ⚙ 設定パネルのラベルも切り替わる。
自作テーマで対応したい場合は *テーマのカスタマイズ* の `@user-vars` を参照。

## テーマのカスタマイズ

### 通常プレビュー

`assets/` フォルダに `.css` ファイルを置くと、`S` キーのスタイル一覧に自動で加わります。選択中のテーマは次回起動時にも復元され、`M` キーのダーク／ライトとは独立に組み合わせられます。

同梱テーマ:

| ファイル | 内容 |
| --- | --- |
| `parchment.css` | 羊皮紙風の暖かいクリーム色テーマ |
| `hakuro-modern.css` | モダンなサンセリフのテーマ（ライト専用） |
| `classical.css` | 格調高い書籍風テーマ（明朝本文＋サンセリフ見出し、ダーク配色も内蔵） |
| `tategaki.css` | 日本語縦書きテーマ（禁則・縦中横・約物詰め。配色は指定しないのでライト／ダークどちらとも合成可）。PDF 出力は A4 横の複数ページ |
| `bunko.css` | **文庫本レイアウト**（下記） |

#### 文庫本レイアウト（`bunko.css`）

`tategaki.css` の縦書きを土台に、**1行を 39 字に固定**して文庫本の字詰めを再現します。本文は **16行ごと**（文庫の1ページ分）に区切られ、ページとページの間には**余白**が入ります。読み進めは縦書きらしく右から左への横スクロール（`tategaki.css` と同じ）。

本物の本と同じように、**段落はページをまたいで分割**されます（続きのページでは字下げしません）。見出しや図表はページをまたがず、入りきらなければ次のページの頭から始まります。

見出し・引用・箇条書きの前後のアキはすべて本文 1 行の整数倍に揃えてある（和文組版でいう**行取り**）ので、各ページはきっちり 16 行になります。

ウィンドウが版面より上下に広いときは、版面を**天地中央**に置きます（狭いときは上端に寄せ、はみ出した分はスクロールで読めます）。

各ページの**地（下）の中央にノンブル（ページ番号）**が入ります。⚙ から表示・非表示を切り替えられます。

字数・行数はもちろん、文字サイズ・行送り・天地の余白・ページ間の余白・段落の字下げ・書体・約物の詰め・ノンブルの有無を、後述の ⚙ から変更できます。変更すると自動的にページを割り直します。

`X` キーで **PDF** に書き出すと、**A4 横 1 枚に 2 ページ分**（見開き。1 ページ目が右）で印刷されます。用紙の四方に 20mm の余白が入り、ページとページの間には見開きのノドにあたる広めのアキが入ります。版面はそれに収まるよう自動的に縮小されますが、**1 行の字数も 1 ページの行数も変わりません**（相似に縮むだけなので組版は崩れません）。⚙ で字数を大きくしていても切れることはありません。図版などで幅の広くなったページは、自動的に 1 枚 1 ページに落ちます。

> 画像・コードブロック・表・数式は大きさが行の整数倍にならないため、それを含むページだけ行数が足りなくなります（文庫レイアウトは元来、地の文のためのものです）。天地の余白を 0 にすると、ノンブルが版面の外へはみ出します。

サンプル: [samples/短編小説.md](samples/短編小説.md)（書き下ろしの短編、23ページ・全10節）／ [samples/縦書き長文.md](samples/縦書き長文.md)

#### スタイルごとの設定（⚙）

`S` キーの一覧で、行の右端に **⚙** が付いているスタイルは、そのスタイル専用の設定を持っています。⚙ を押すとスライダーなどの設定パネルが開き、**動かすとその場でプレビューに反映**されます（再描画は起きません）。設定はスタイルごとに保存され、次回起動時にも復元されます。「既定に戻す」でそのスタイルの既定値に戻ります。

**設定できる項目はスタイルによって異なります**（`bunko.css` は 10 項目、`tategaki.css` は 3 項目、その他の同梱テーマは設定項目なし＝⚙ も出ません）。項目は CSS 側が自分で宣言する仕組みで、自作テーマにも同じように付けられます。CSS のどこか（慣例としてファイル末尾）に次のようなコメントを書くだけです。

```css
#preview {
    font-size: var(--mytheme-font-size, 17px);
}

/* @user-vars
[
  { "var": "--mytheme-font-size", "label": "文字サイズ",
    "type": "length", "min": 12, "max": 28, "step": 1, "default": 17, "unit": "px" },
  { "var": "--mytheme-accent", "label": "アクセント色",
    "type": "color", "default": "#0366d6" }
]
*/
```

型は 4 種類:

| `type` | UI | CSS に渡る値 |
| --- | --- | --- |
| `number` | スライダー | 数値そのまま（`calc()` の係数に使えます。`unit` は表示だけに使われる単位ラベル） |
| `length` | スライダー | 数値 + `unit`（`px` / `em` / `%` など） |
| `select` | プルダウン | `options` に列挙した `value` のいずれか |
| `color` | 色見本＋チェックボックス | 色の値（チェックを外すと `transparent`） |

範囲外の値・宣言にない値は自動的に既定値へ戻されるので、テーマ側で項目を増減しても壊れません。

`label` の隣に **`labelEn`**（`options` の各項目でも同じ）を書いておくと、UI の表示言語が
English のときにそちらが使われます。書かなければ `label` が両方の言語で使われるだけなので、
既存のテーマや自作テーマがこれで壊れることはありません。`unit` にも同様に **`unitEn`** を
書けますが、**`type: "number"` のときだけ**です — `length` の `unit` は実際の CSS 値に入る
本物の単位（`px` / `em`）なので訳してはいけません。

```json
{ "var": "--mytheme-font-size", "label": "文字サイズ", "labelEn": "Font size",
  "type": "length", "min": 12, "max": 28, "step": 1, "default": 17, "unit": "px" }
```

> `/* @user-vars ... */` コメントの中身は JSON としてそのまま読まれます。同じコメント内に
> 説明文を書くと宣言全体が読み込めなくなり（⚙ が出なくなり）ます。注記は別のコメントに書いてください。

> ⚙ で変えた値は `X` キーの HTML / PDF エクスポートにも反映されます（Marp テーマの「テーマ色」も同様）。テーマが `@import` で他の CSS を読み込んでいる場合、その中身もエクスポート時に取り込まれます（`bunko.css` は `tategaki.css` を読み込んでいます）。

### Marp スライドのテーマ

`assets/marp/` フォルダに、先頭に `/* @theme テーマ名 */` を書いた CSS を置くと使えるようになります。
Markdown 側の front-matter で指定するか、Marp 表示中に **`S` キー**で一覧から選びます（選ぶと front-matter の `theme:` 行が書き換わります）。

```yaml
---
marp: true
theme: magenta    # ← assets/marp/magenta.css のテーマ名
---
```

Marp 標準の `default` / `gaia` / `uncover` に加えて、**同じデザインの 8 色ファミリー**を同梱しています（見本: [samples/marp-themes.md](samples/marp-themes.md)）。

| `theme:` | 配色 | 向き |
|---|---|---|
| `magenta` | マゼンタ × ティール | 基本形。非ブランドで目立つ |
| `indigo` | 藍 × 朱 | 落ち着いた技術資料 |
| `purple` | 紫 × ティール | |
| `green` | 深緑 × ブルーグレー | |
| `gold` | 古金 × ネイビー | 式典・表彰・格式 |
| `silver` | 寒色グレー × スチールブルー | モノトーン寄り |
| `black` | 墨のモノクロ | 差し色だけがテーマ色に追随 |
| `dark` | 暗色背景 × マゼンタ | 暗い会場向け |

どのテーマも `<!-- _class: title -->`（表紙）/ `<!-- _class: section -->`（章扉）/ **`<!-- _class: invert -->`（そのスライドだけ暗色化）** が使えます。

**⚙ テーマ色（1 つのピッカーで配色全体が追随）** — `S` キーの一覧で、選択中のテーマの行にある **⚙** を押すと「テーマ色」のカラーピッカーが 1 つだけ現れます。見出し・罫線・引用の地・インラインコードの地・章扉のグラデーション・透かし・レーザーポインタ・選択マーカーまで、配色のすべてがその 1 色から導かれているので、動かすだけで全体が追随します。**色相と鮮やかさだけが反映され、明度はデザイン側で固定**されているため、淡い色を選んでも見出しは読める濃さを保ちます（灰色を選べば silver 風に）。設定はテーマごとに保存され、HTML / PDF 書き出しにも反映されます。「既定に戻す」でデザイン済みの配色に戻ります。

**自作バリエーション** — `magenta.css` を `@import` して `--theme-color` と派生式を書き換えるだけです。

```css
/* @theme mytheme */
@import "magenta";
:root {
  --theme-color: #00695c;
  /* magenta.css の :root を写し、L（明度）/ K（彩度比）/ ΔH（色相差）を好みに変える */
  --accent: oklch(from var(--theme-color) 0.5313 c h);
}
```

末尾に `/* @user-vars … */`（`indigo.css` などをコピー）を置けば ⚙ も付きます。

### 機密表示（Confidential）／任意の透かし文字（watermark）

文書の front-matter に `confidential: true` を書くと、ページ全体に「機密（CONFIDENTIAL）」の斜め透かしが重なります（文書ごとの指定）。

```yaml
---
confidential: true
---
```

「CONFIDENTIAL」以外の任意の文字を透かしにしたいときは、代わりに **`watermark: <文字列>`** を指定します（`DRAFT` / `社外秘` / `SAMPLE` など）。オーバーレイの色・書体・角度・サイズは `confidential: true` と全く同じ仕組みで各テーマ CSS が決め、文言だけが差し替わります。両方を書いた場合は `watermark:` の文言が優先されます。

```yaml
---
watermark: DRAFT
---
```

**見た目は各テーマ CSS が定義します。** 本体（`index.html`）は `body.confidential` クラスを付けるだけで、透かしの文言・色・大きさ・角度・フォント・不透明度は `--confidential-*` カスタムプロパティで各 CSS が上書きします（`#preview` / `:root` / `section` のいずれに指定しても継承されます）。

| 変数 | 用途（既定値） |
| --- | --- |
| `--confidential-label` | 表示文字列（`"CONFIDENTIAL"`） |
| `--confidential-color` | 透かし色 |
| `--confidential-size` | 文字サイズ |
| `--confidential-angle` | 回転角（`-30deg`） |
| `--confidential-font` | フォント |
| `--confidential-opacity` | 不透明度（`0` で完全非表示） |

同梱テーマはそれぞれ配色に合わせた透かしを定義済みです（例: `tategaki.css` は縦組みの「社外秘」）。透かしは通常プレビュー・Marp スライドの両方で機能し、`X` キーの HTML / PDF エクスポートにもそのまま反映されます。サンプル: [samples/confidential.md](samples/confidential.md)（`confidential: true`）／ [samples/draft.md](samples/draft.md)（`watermark: DRAFT`）

## エディタウィンドウ（`E` キー）

`E` キーを押すと、現在プレビューしている Markdown ファイルを編集するための **別ウィンドウ** が開きます。CodeMirror 6 + Vim キーバインドのミニマム UI で、論文の下書き・エッセイ・小説の執筆を想定しています。通常のテキストベース編集に加えて、`---` 区切りをセルとして扱う **Jupyter 風のセルモード**も選べます。

### 主な機能

- **Vim モード（任意）** — `@replit/codemirror-vim` による Vim キーバインド。デフォルトは OFF。`:w` / `:wq` / `:q` も使えます。
- **Dvorak 配列エミュレータ対応** — やまぶき等で Dvorak 配列を使っていると、Vim のコマンドが「出力された文字」で解釈されるため `hjkl` などの指の記憶がそのまま使えません。`⚙ 設定` モーダルの **「キー配列（Vim コマンド）」を Dvorak** にすると、**コマンドモード（ノーマル / ビジュアル / オペレータ待機）** のキーだけが**押した物理キーの QWERTY 位置**で解釈されるようになります（`hjkl`・`dd`・`gg`・`3j`・`[[` などがすべて QWERTY の位置どおりに効きます）。**インサートモードでの文字入力、ex コマンドライン (`:`) と検索 (`/`) の中身は Dvorak のまま**なので、文章は普段どおりタッチタイプできます。`f` / `t` / `r` / `m` の引数として打った文字もそのまま扱われます。Vim の ex コマンド `:set dvorak` / `:set nodvorak` / `:keylayout [qwerty|dvorak]` でも切替可能。既定は OFF（変換なし）。
- **日本語のワード単位移動** — Vim の `w` / `b` / `e`（および `W` / `B` / `E` / `ge`、INSERT の `Ctrl+W`）が、漢字・ひらがな・カタカナ・英数字・記号の**文字種の切れ目**で止まります。`dw` / `cw` / `daw` / `diw` などのオペレータ付きでも同じです（`ー` はカタカナ扱いなので「ラーメン」は 1 語）。Vim OFF のときの挙動は変わりません。
- **OS クリップボード連携（ヤンク / ペースト）** — Vim の `y` / `d` / `c` / `x` は **Windows のクリップボードにも**コピーされ、`p` / `P` はクリップボードの内容を貼り付けます。エディタウィンドウ同士や、他のアプリとの間でそのままコピー＆ペーストできます（`"+y` / `"+p` も使えます）。
- **保存（`Ctrl+S`）** — ディスクへ書き込み、プレビューに即時反映（チラつきなし）。
- **ライブプレビュー** — タイプ中も未保存内容がプレビューへ即時反映（保存はせず、タイトルバーの dirty ドットも変化しません）。
- **オートコンプリート**
  - **front-matter 補完** — 先頭の `---` … `---` ブロックの中でキーと値を補完します。`marp` / `confidential` / `watermark` / `title` は常に、`theme` / `paginate` / `size` / `header` / `footer` / `class` / `_class` / `math` などの Marp 用キーは `marp: true` が書かれているときだけ候補に出ます。値も列挙され、`theme:` には Marp 標準の `default` / `gaia` / `uncover` に加えて **`assets/marp/` に置いた自作テーマ名**が並びます。空の項目にカーソルを置くと自動的に候補が開くので、キー名を覚えていなくても選べます。
  - **KaTeX コマンド補完** — 数式コンテキスト（`$…$` / `$$…$$` / `\begin{}…\end{}` の内側）で `\` を打つと、約 200 個の KaTeX コマンド候補がカテゴリ別（greek / operator / relation / arrow / big-op / function / decoration / font / delim / spacing / env / symbol）で並びます。選択時はコマンド種別に応じてテンプレートが挿入され、カーソルが適切な位置に配置されます: `\alpha` などの記号は素挿入、`\sqrt{}` / `\hat{}` などは引数ブレース内、`\frac{}{}` / `\binom{}{}` は第 1 引数ブレース内、`\sum` / `\int` / `\lim` は `_{}^{}` の下付きブレース内、`\begin` / `\end` は環境名補完へ繋ぎます。コードフェンスや通常文中では発火しません。
  - **KaTeX 環境名補完** — `\begin{` の直後に環境名候補（`align`/`matrix`/`cases` ほか）。確定するとカーソルは本文に置かれ、`\end{name}` が自動付加されます。
  - **パス補完** — Markdown リンク `](…` で同階層のファイル・フォルダ名を補完。フォルダ選択時は `/` が追加されてさらに下へ潜れます。
  - **フェンスドディビジョン補完（`:::`）** — 行頭で `:::` を打つと配置・カラムのキーワード候補（`center` / `right` / `left` / `message` / `columns` / `columns-2` / `columns-3` / `columns-4`）が出ます。確定すると閉じ `:::` まで自動挿入され、カーソルは本文行に置かれます（columns 系は列数に応じた `+++` 区切りも雛形に挿入）。開いているブロック内で閉じ `:::` を打つときは候補を出さないので、Enter で誤確定しません。
- **インデント（`Tab` / `Shift+Tab`）** — 行やブロックの字下げ／戻しができます。数字付きリスト（`1. …`）の中では、インデント幅が**マーカーの文字幅に自動で合います**（`1. ` なら 3 桁、`10. ` なら 4 桁）。CommonMark / GFM は「子要素をマーカー直後の桁に揃える」ことを求めるため、既定の 2 桁のままだと `1. 項目` の下に `- 子項目` を書いてもリストが入れ子にならないからです。行頭でマーカーの直後に `Tab` を押すと、その行ごと 1 段下げてサブリストにできます。数式コンテキストでは従来どおり数式入力支援（下記）が優先されます。
- **章立て畳み** — 見出し（`#`, `##`, …）の左ガターをクリックで折りたたみ。Vim NORMAL では `za` で現セクションのトグル、`zA` で全見出しの一括トグル（畳んだ状態でもすべてのヘディング行は表示されたまま）。
- **見出しジャンプ** — Vim NORMAL で `]]` / `[[` で次／前の ATX 見出しへカーソル移動。
- **YaTeX 相当の数式入力支援** — `$`+`Tab` → `$|$`、`$$`+`Tab` → 表示数式ブロック、`\begin{env}`+`Tab` → 対応する `\end{env}`、数式内で `\frac`/`\sqrt`/`\sum`/… の補完、インライン数式内で `a.` → `\alpha` のようなギリシャ文字略記。さらに **`\left<区切り>` の自動ペア挿入**: 数式内で `\left` の直後に `(` `[` `\{` `\|` `|` `<` `/` `.` `\langle` `\lfloor` `\lceil` `\lgroup` `\lmoustache` `\backslash` のいずれかを入力すると、Tab を介さず即座に対応する `\right<閉じ>` がカーソル後ろに挿入されます（例: `\left(` → `\left(|\right)`、`\left\langle` → `\left\langle|\right\rangle`、`\left.` → `\left.|\right.`）。カーソルは開きの直後にとどまります。すでに対応する `\right` がある場合は二重挿入を抑止し（`\right` が離れた位置にあっても検出するので、既存の `\left(x + y\right)` の開き側を打ち直しても重複しません）、コードフェンスや本文中では発火しません。自動挿入された `\right<閉じ>` は普通に削除できます（Vim の `d$` / `x` などで消しても復活しません）。またカーソルがペアのちょうど間にあるときは **Backspace 1 回で `\left…` `\right…` の両方**が消えるので、意図しない補完をすぐ取り消せます。
- **文字数カウントモーダル** — ステータスバーの文字数表示をクリックするとモーダル表示（総文字数・空白除外・本文のみ（YAML/コード/数式除外）・単語数・行数・段落数、選択範囲があれば内訳）。キーバインドは割り当てていません（`C` は Vim の change-to-EOL のため）。
- **表（テーブル）支援** — **雛形の挿入**: 行数・列数（と揃え）を指定して GFM のパイプ表を挿入します。行数は見出し行を含む数です。**カーソル列のハイライト**: カーソルがあるセルの列を、その表の全行にわたって淡く強調します（見出し行も対象、区切り行は対象外）。呼び出しは、ステータスバーの `⊞ Table` ボタン（列ハイライトの ON/OFF は `⚙ 設定` モーダル内）／ Vim の ex コマンド `:table` `:tbl` `:tablecol`（`:table 3 4`・`:table 3x4`・`:table 4`（正方）・`:table 3 4 center` など。引数なしはモーダル）／ `:set tablecolumn` `:set notablecolumn`（`tcol` / `notcol`）／ Vim NORMAL の `gti`（挿入）`gtc`（ハイライト切替）／ 非 Vim の `Ctrl+Alt+T` `Ctrl+Alt+H`。ハイライトの ON/OFF は `localStorage` に永続化されます（既定 ON）。
- **Office の表を貼り付けて GFM の表に変換** — **`Ctrl+V`** でクリップボードの表を **GFM のパイプ表に自動変換** して挿入します。Excel・Word・PowerPoint・ブラウザからのコピー（HTML の `<table>`）と、Excel のタブ区切りテキストの両方に対応。プレビュー側の「Copy table」の逆方向なので、コピーして貼り戻す往復ができます。結合セル（rowspan / colspan）は展開して複製し、列幅は全角文字を 2 幅として揃えます。セル内の改行は半角スペースに畳まれ、`|` は自動でエスケープされます（太字などのインライン書式は保持しません）。
  - **表でないものは従来どおり素のまま貼り付け**られます。タブでインデントされたコードや、表と地の文が混ざった Word の選択範囲（変換すると地の文が消えてしまうため）は変換しません。コードフェンス・インラインコード・既存の表・YAML front matter の中でも変換しません。
  - **取り消し** — 誤変換は **`Ctrl+Z` 一回**で貼り付けごと戻ります。**`Ctrl+Shift+V`** ならその一回だけ素のまま貼り付け。恒久的に無効化するには `:set notablepaste`（`:set tablepaste` で復帰、`localStorage` に永続化、既定 **ON**）。
  - Vim 使用時は INSERT モードの `Ctrl+V` で変換されます（NORMAL モードの `Ctrl+V` は矩形選択のままです）。Vim の `p` は変換せず、レジスタの内容をそのまま貼り付けます。
- **Marp スライド編集支援**（`marp: true` の文書でのみ有効）— **スライド挿入**: クラス（`none` / `title` / `section` / `lead` / `invert` / `split`）をモーダルから選ぶと、カーソルのあるスライドの直後に新しいスライド（`---` + `<!-- _class: … -->`）を挿入。**スライドの切り取り・コピー**: カーソルを含むスライド 1 枚分（先頭 `---` 込み）をシステムクリップボードへ。切り取りは区切りを二重に残さないよう 1 本分まで除去します。呼び出しは、ステータスバーのボタン（`+ Slide` / `⧉ Slide` / `✂ Slide`、Marp 文書時のみ表示）／ Vim の ex コマンド `:slide` `:slideyank` `:slidecut` ／ Vim NORMAL の `gsi`（挿入）`gsy`（コピー）`gsd`（切り取り）／ 非 Vim の `Ctrl+Alt+N` `Ctrl+Alt+C` `Ctrl+Alt+X`。いずれも既存の Vim コマンドと衝突しません。
- **セルモード（Jupyter 準拠）** — `⚙ 設定` モーダルで「セルモード」を ON にすると **`---` 区切りが「セル」** として扱われ、Jupyter と同じ操作感で塊ごとに編集できます。Marp 文書に限らず、すべての `.md` で使えます（`---` はスライド境界と同じ単位なので、Marp では**セル N = スライド N**）。
  - **2 つのモード** — `Esc` で**コマンドモード**（アクティブセルの左バーが青、キャレットは非表示）、`Enter` / `i` で**編集モード**（左バーが緑）に戻ります。Vim を ON にしていても NORMAL モードの `Esc` が入口になり、INSERT / VISUAL 中の `Esc` は従来どおり Vim のものです。
  - **コマンドモードのキー** — `j` / `k`（前後のセルへ）、`a` / `b`（上 / 下に挿入）、`dd`（削除）、`x` / `c` / `v` / `V`（カット / コピー / 下・上に貼り付け）、`M`（下のセルと結合）、`1`〜`6` / `0`（見出しレベルの設定 / 解除）、`gg` / `G`、`z` / `u`（元に戻す）、`s`（保存）、`f`（検索）、`m`（Marp のスライドクラス変更）、`h`（キー一覧）。**どの操作も `u`（`Ctrl+Z`）1 回で完全に元に戻ります。**
  - **実行（プレビュー同期）** — `Shift+Enter` で同期して次のセルへ、`Ctrl+Enter` で同期してとどまる、`Alt+Enter` で同期して下に新しいセルを作成。`Ctrl+Shift+-` でカーソル位置で分割、`Ctrl+Shift+↑ / ↓` でセルを入れ替え。**`Live: OFF` と組み合わせると、プレビューは実行したときだけ更新される完全に手動のワークフロー**になります。
  - **表示** — 各セルが枠で囲まれ、左のガターに `[1]` `[2]` … のセル番号が付きます。`---` 行は薄く表示されてセルの隙間になります。先頭の YAML front-matter は灰色バーの**保護セル**で、移動対象にならず削除・結合・分割も拒否されます。
  - **呼び出し** — `⚙ 設定` モーダルの「セルモード」 ／ Vim の ex コマンド `:cellmode`・`:set cells` / `:set nocells` ／ Vim NORMAL の `gmc`。設定は `localStorage` に永続化（既定 **OFF**）で、OFF に戻せば装飾・セル番号・キー割り当てはすべて消え、従来のテキスト編集に戻ります。[セルモードのサンプル](samples/cells.md) 参照
- **文字サイズの拡縮** — **`Ctrl` + `+`（`=`）／ `Ctrl` + `-` ／ `Ctrl` + `0`（既定に戻す）**、および **`Ctrl` + マウスホイール** で編集中の文字を拡大・縮小できます（9〜32px、既定 15px）。拡縮するのは**編集領域の文字と行番号だけ**で、ステータスバーやモーダルの文字は一定のままです。設定は `localStorage` に永続化され、次に開いたときも維持されます。Vim では `:fontsize 17`（絶対）・`:fontsize +2` / `-2`（相対）・`:fontsize`（既定に戻す）も使えます。
- **フォントの変更** — 編集領域のフォントを **Cascadia Code（既定）／ Consolas ／ BIZ UDゴシック ／ 游ゴシック** から選べます（設定モーダル内）。日本語の読みやすさはサイズだけでなく書体にも左右されるためです。
- **設定モーダル（`⚙ 設定`）** — 上端ホバーで現れるステータスバーの **`⚙ 設定`** ボタン（または Vim の `:pref`）から、**文字サイズ・フォント・テーマ（Light / Dark）・行番号（絶対 / 相対 / なし）・Vim キーバインド・キー配列（Vim コマンド）・セルモード・表の列ハイライト・表の貼り付け変換・ライブプレビュー**をまとめて設定できます。各項目にはショートカットや ex コマンドも併記されています。設定はいずれも `localStorage` に永続化されます。ステータスバーに残るのは**操作ボタンだけ**（`⚙ 設定` / `⊞ Table`、および Marp 文書でのみ現れるスライド 3 ボタン）です。
- **プレビュー連動** — プレビュー側でファイルを切り替えるとエディタも追従。Rust 側で 1:1 ペアリングしているので、複数ペアを開いても混線しません。
- **未保存で閉じた場合** — ダーティ状態のままエディタを閉じる（Vim `:q!` やウィンドウの × ボタン）と、プレビューはディスク上の内容に自動復帰します。
- **オフライン** — すべてバンドル済み、ネット接続不要。

## HTML / PDF エクスポート（`X` キー）

`X` キーを押すと「名前を付けて保存」ダイアログが開きます。ダイアログの **ファイル種類（拡張子）で `HTML` と `PDF` を選ぶだけで出力形式が切り替わります**。`.html` を選ぶと現在のプレビュー内容を **単一の `.html` ファイル** として書き出します。エクスポートされた HTML には次がすべてインラインで含まれており、追加ファイルなしでそのまま閲覧・配布できます。

- レンダリング済みの本文 DOM
- 適用中のテーマ CSS
- Mermaid は SVG として展開
- KaTeX 数式はレンダリング済み HTML として埋め込み
- 画像は Base64（エクスポート時にインライン化して自己完結）
- ローカル動画は `media/` フォルダにコピーして相対パス参照（YouTube はそのまま）
- 目次サイドバー（折りたたみ・スクロールスパイ・スムーズスクロール）
- 脚注ポップアップ用のスクリプト

社内 wiki への貼り付け、メール添付、静的 Web サーバへのアップロードなどにそのままお使いいただけます。

### PDF エクスポート（単一ファイル）

保存ダイアログで **`PDF`** を選ぶと、現在のドキュメントを **PDF** として書き出します（WebView2 の印刷機能を利用）。

- **見出しから「しおり（ブックマーク）」を自動生成** — PDF ビューアのしおりパネルから目次として辿れます
- **リンクがクリック可能** — 本文中のリンク・脚注・脚注の戻りリンクなど、内部・外部リンクがそのまま PDF のリンク注釈になります
- テキスト選択可能なベクター出力、テーマの背景色も保持（通常の文書は A4 縦）
- **Marp スライドは「1 ページ = 1 スライド」** — スライドと同じ大きさの用紙に、**余白なし**でスライドが 1 枚ずつ収まります。`size: 4:3` を指定した文書は 4:3 の用紙になり、背景色・背景画像も紙の端まで印刷されます。**表示モード（`P` キー）がスクロール / デッキ / 一覧のいずれでも結果は同じ**です
- **縦書きテーマは A4 横の複数ページ** — `tategaki.css` / `bunko.css` を選んでいるときは、用紙が **A4 横**になり、本文が右から左へ何ページにも分けて印刷されます。`bunko.css` は **1 枚に 2 ページ分（見開き。1 ページ目が右）**で、ページの間には見開きのノドにあたる広めのアキが入ります。`tategaki.css` は 1 行の長さも 1 ページの行数も**紙のサイズから自動的に**決まります。用紙の余白は四方 20mm 取ってあり、`bunko.css` では版面がそこに収まるよう自動的に縮小されます（1 行の字数・行数は変わりません）。どちらもノンブル・しおり・リンク・テキスト選択はそのまま使えます
- **動画は静止画フレームに差し替え** — ローカル動画はその瞬間のフレームを画像化して PDF に載せます。フレーム時刻は alt の `|t=<時刻>` で指定（省略時は現在の再生位置。詳細は上の「動画 / YouTube 埋め込み」）

> **補足**: PDF 出力は **単一ファイル表示時のみ**（ワークスペースモードの `X` は従来どおり HTML フォルダ一括出力）。しおりの自動生成には比較的新しい WebView2 ランタイムが必要です（未対応環境ではしおり無しになりますが、リンクのクリックは常に機能します）。オートフィット（`A` キー）の下限まで縮めても入りきらないスライドは、画面表示と同じくはみ出した部分が切れます。縦書きテーマでは、図版などで 1 枚に収まらないほど幅の広くなったページは、はみ出した部分が切れます。

## PNG 出力（`--export-png`）— AI エージェント向けの自律レイアウトチェック

Claude などのエージェント AI に Marp スライドを作らせるとき、**エージェント自身がレンダリング結果を見てレイアウトの崩れ（本文はみ出し・詰まり・図の切れなど）を確認し、自己修整する**ための非対話コマンドです。ウィンドウは表示されず（非表示のまま描画）、撮影が終わると自動終了します。

```
md-previewer.exe <file.md|.mdx> --export-png <出力ディレクトリ> [--slides 1,3,5-7] [--png-scale 2]
```

- **Marp 文書** — スライド 1 枚ごとに `slide-01.png`, `slide-02.png` …（論理 1280×720、`--png-scale`（既定 2）倍の解像度）。`--slides` で対象を絞れます（1 始まり、`1,3,5-7` のような範囲指定。省略時は全スライド）。
- **通常の Markdown 文書** — 全文を縦長 1 枚の `page.png` に。
- **`layout.json`** — つねに出力。各スライドの `overflow`（枠を超えたか）・`scale`（適用された自動縮小倍率、`<1` なら縮小された）・`flooredAtMin`（縮小下限 0.5 でもなお溢れている＝**要修整の確定シグナル**）・`contentH` / `avail` を記録。エージェントはまず JSON で怪しいスライドを安価に切り分け、必要な PNG だけを見て判断できます。

典型的なループ: **Markdown を書く → `--export-png` → `layout.json` で崩れたスライドを特定 → その PNG を見て確認 → Markdown を直す → 再実行**。

> **補足（既知の制限）**: 撮影プロセスは連続起動せず 1 本ずつ順に実行してください（WebView2 の後片付け／ユーザーデータのロックが一時的に競合することがあります）。進捗・エラーは exe と同じ場所の `md-previewer.log` に記録されます。

## オプション拡張：スタイル別エクスポータ

任意の `.css` テーマには、専用の HTML 出力ロジックを差し込むことができます。命名規約は次のとおりです:

- `assets/<base>.css` に対して、同階層に `assets/<base>_export.js` を置く
- そのモジュールは `export async function exportStyle({ currentMarkdown, currentFilePath, preview })` を持つ

このペアが見つかったスタイルが active のときに `X` キーを押すと、汎用 HTML エクスポートの代わりに `exportStyle` が呼ばれます。マップは起動時に Rust ホストが組み立てて `window.__styleExporters` として注入します。該当ファイルが無い場合は汎用パスにフォールスルーします。

## 既知の制限

- **Windows 専用**（macOS / Linux 非対応）
- **閲覧が主目的**（編集は補助機能。`E` キーで内蔵エディタを開けますが、メイン UI はあくまでプレビュー。外部エディタで編集 → 保存しても自動再読み込みされます）
- **Marp モードでは以下が無効になります**:
  - 目次サイドバー（**deck モードのみ非表示**。scroll / list モードではスライド目次が表示されます）
  - `M` キーによるテーマ切替（Marp 側のテーマが優先）
  - `N` キーによるセクション自動番号
  - エディタとのスクロール同期
- **表の編集（プレビュー側）の制限**:
  - 対象は**先頭階層の GFM パイプ表のみ**。引用・リスト・段組みの中に入れ子になった表、`csv` / `tsv` コードブロックの表、Marp スライドの表は編集できません（`csv` / `tsv` は描画時にフェンス内の空行や末尾空白が落ちるため、書き戻すと元データと一致しなくなります）
  - 保存時に、行数・列数が違う行（ragged な表）は見出しの列数に合わせて整えられます。列数を超えるセルは失われます
  - **エディタウィンドウに未保存の変更があるときにプレビュー側から保存すると、その変更が上書きされることがあります**（エディタで入力している間はライブ更新が届いて編集が中断されるため、実際に踏むのは稀です）。同じファイルを両方で同時に編集するのは避けてください
  - 元に戻す操作（Undo）はありません。「取消」は確定前の編集を破棄するだけです

## ライセンス・サードパーティ表記

本アプリは複数の OSS ライブラリ（marked / highlight.js / KaTeX / Mermaid / Marp Core / CodeMirror / @markwhen/parser / feynmark など）を同梱しています。各ライブラリの著作権表示・ライセンス全文は **`assets/THIRD_PARTY_LICENSES.txt` の 1 ファイルに集約** されています。

このファイルは `tools/collect-licenses.ps1` により自動生成される成果物のため、**本リポジトリには含まれていません**（git-ignored）。ただし、立場によって扱いが異なります。

- **配布版のインストーラ（`MdPreviewer-Setup-*.exe`）を使うエンドユーザー** — 何もする必要はありません。インストーラには `assets/THIRD_PARTY_LICENSES.txt` が同梱されており、インストール後すぐに利用できます。スタートメニューの **"Third-party Licenses"** ショートカット、またはアプリ起動中 `H` キー → ヘルプダイアログ右下の **Third-party licenses** リンクから閲覧できます。
- **ソースからビルドして実行可能な状態にする開発者** — ライセンスファイル自体はアプリの起動に必須ではありませんが、**配布用インストーラを作成する前には必ず生成が必要** です（`installer/md-previewer.iss` が `assets\*` を recurse で取り込むため、ファイルが無いと `iscc` でビルドしても同梱されません）。`build-installer.ps1` 経由でビルドすれば自動で再生成されます。手動で再生成する場合、および `tools/build-marp/` や `tools/build-editor/` の依存を更新した場合は、次のいずれかを実行してください:

  ```powershell
  pwsh -File tools/collect-licenses.ps1
  # もしくは tools/install-deps.ps1 -Licenses
  ```

## ソースからビルドする場合（開発者向け）

### 一括ビルド（推奨）

リポジトリ直下の `build.ps1` を実行すると、依存ライブラリ取得 → アイコン生成 → `cargo build --release` → `assets\` を `target\release\assets\` へ同期、までを一気通貫で行います。冪等なので、2 回目以降は完了済みステップをスキップします。

```powershell
.\build.ps1                 # 新規 clone からのフルビルド（release）
.\build.ps1 -DebugBuild     # debug ビルド（target\debug\ へ出力）
.\build.ps1 -Clean          # cargo clean + assets\libs\ 削除 → フル再生成
.\build.ps1 -ForceDeps      # install-deps.ps1 -Force を強制実行
.\build.ps1 -SkipAssetCopy  # cargo build のみ、assets コピーをスキップ
```

`build.ps1` は `assets\libs\editor\editor.iife.js` などのセンチネルファイルを見て、未取得時のみ `tools\install-deps.ps1` を呼び出します。アイコン（`assets\icon.ico`）も未生成時のみ `tools\make-icon\make_icon.py` を実行します。Inno Setup によるインストーラ生成は **行いません** — 配布用インストーラを作る場合は次の `build-installer.ps1` を使ってください。

### インストーラのビルド

配布用の `MdPreviewer-Setup-<version>.exe` を生成するには、リポジトリ直下の `build-installer.ps1` を使います。`build.ps1` → `tools\collect-licenses.ps1`（`assets\THIRD_PARTY_LICENSES.txt` 再生成）→ `iscc installer\md-previewer.iss` を順に実行します。

```powershell
.\build-installer.ps1                          # フル一括（build + licenses + iscc）
.\build-installer.ps1 -SkipBuild               # ビルド済みを再利用
.\build-installer.ps1 -SkipLicenses            # 既存の THIRD_PARTY_LICENSES.txt を再利用
.\build-installer.ps1 -Iscc 'C:\...\ISCC.exe'  # ISCC の場所を明示
```

`ISCC.exe` は PATH から検索し、見つからなければユーザー単位インストール (`%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`) → マシン単位インストール (`Program Files (x86)\Inno Setup 6\ISCC.exe`) の順に試します。出力は `dist\MdPreviewer-Setup-<AppVersion>.exe`（AppVersion は `installer\md-previewer.iss` から読み出し）。前提として **Inno Setup 6**（[公式サイト](https://jrsoftware.org/isdl.php)）のインストールが必要です。

### リリースの自動化（main ブランチ更新時）

`main` ブランチがマージ（`git merge` / `git pull`）で更新されると、追跡された git フックがリリース処理を開始します。`HISTORY.md` はインストーラに同梱され**インストール直後に自動で表示される**ため、生成したままの下書き（コミット件名の羅列）が利用者の目に触れないよう、処理は **2 段階** に分かれています。

**第 1 段階（マージ時に自動実行）** — バージョンを採番してファイルを書き換えるだけで、**ビルド・コミット・タグ付けは行いません**。

1. 前回リリースタグ (`v*`) 以降のコミットからバージョン種別を判定（破壊的→major / 利用者向けの機能追加→minor / それ以外→patch）し、新バージョンを採番。
2. `Cargo.toml` / `installer\md-previewer.iss` / `HISTORY.md` の 3 箇所を更新。`HISTORY.md` の先頭には `## v<X.Y.Z>` 節が挿入され、利用者向けのコミットは箇条書きの下書きとして、内部作業（`refactor:` / `test:` / `docs:` など）は参考情報として HTML コメント内に列挙されます。
3. 節の先頭に `TODO(release-notes)` のレビューマーカーが置かれます。

バンプ種別が意図と違うときは、変更を破棄し `-Bump` を明示してやり直せます。

```powershell
git checkout -- Cargo.toml installer/md-previewer.iss HISTORY.md
pwsh -NoProfile -File tools\release-on-main.ps1 -Bump patch
```

**リリースノートの手直し** — `## v<X.Y.Z>` 節を、利用者が読んで得をする内容に書き換えます。観測できない内部変更は落とし（内部作業だけの回は「内部改善（動作の変更はありません）」の 1 行で十分）、実装ではなく**利用者にとって何が変わるか**を `- **機能名** — 説明。` の形で書き、1 つの機能に分かれたコミットはまとめます。参考情報側に利用者向けの修正が紛れていないかも確認してください。仕上げに `TODO(release-notes)` のコメントブロックを削除します。

**第 2 段階（`-Finalize`）** — レビューマーカーが残っていると**中止**するので、未レビューのまま確定できません。マーカーが消えていること・バージョン 3 箇所が一致すること・タグが未使用であることを確認したうえで、インストーラをビルドし、**ビルド成功時のみ**コミットとタグ `v<X.Y.Z>` を作成します（push は行いません）。

```powershell
pwsh -NoProfile -File tools\release-on-main.ps1 -Finalize
```

**公開前の検査と push** — `-Verify` はいつでも実行できる機械的な検査です（バージョン整合性・レビューマーカー・タグ位置に加え、**インストーラに同梱されたリリースノートが現在の `HISTORY.md` と一致するか**をハッシュで照合）。

```powershell
pwsh -NoProfile -File tools\release-on-main.ps1 -Verify
git push origin main; git push origin v<X.Y.Z>
```

`MDP_RELEASE_PUSH=1` を設定しておくと push まで自動で行います。`-Finalize` 中にインストーラのビルドが失敗した場合、コミットもタグも作られずバージョン変更は作業ツリーに残るので、ビルドを直してから `-Finalize` をやり直してください（手でコミットしないこと）。マージ前の下見には `-DryRun`（第 1 段階の判定結果のみ表示）、main 以外での実行には `-Force` が使えます。

フックは `core.hooksPath`（ローカル設定）で有効化されるため、**clone 毎に 1 回**有効化が必要です。`tools\install-deps.ps1` が自動で設定しますが、手動なら次を実行します:

```powershell
pwsh -File tools\install-hooks.ps1
```

### 手動で段階的に実行する場合

GitHub からクローンした直後の `assets/libs/` は空です。サードパーティ JS/CSS/フォントと、Marp / エディタ用の esbuild IIFE バンドルはコミットされていないため、最初に一度だけ次のコマンドで取得・ビルドしてください。

```powershell
pwsh -File tools\install-deps.ps1
```

これで `tools/fetch-libs.ps1`（marked / mermaid / KaTeX + フォント / highlight.js を cdnjs・jsdelivr からピン留めバージョンでダウンロード）と、`tools/build-marp/` / `tools/build-editor/` / `tools/build-markwhen/` の `npm install && npm run build` が順に走り、`assets/libs/` 配下が完成します。フラグ:

- `-Force` — 静的ライブラリを再ダウンロード（既存ファイルを上書き）
- `-SkipNode` — CDN ダウンロードのみ実行（Node がない環境用）
- `-Licenses` — 仕上げに `tools/collect-licenses.ps1` を呼び `assets/THIRD_PARTY_LICENSES.txt` を再生成

この後の `cargo build --release` 等の手順は [`CLAUDE.md`](CLAUDE.md) の "Build & Run Commands" を参照してください。
