### Build / installer / icon

- `build.rs` + `app.rc` + `assets/icon.ico` — Windows icon embedding. `build.rs` invokes the `embed-resource` build-dep to compile `app.rc` (a one-line Win32 resource script: `IDI_ICON1 ICON "assets/icon.ico"`), which embeds the multi-resolution `.ico` into the release exe so Explorer / taskbar / window chrome / `.md` file thumbnails (via the registry `DefaultIcon` pointing at `md-previewer.exe,0`) all use it. Only compiles on Windows targets.
- `tools/make-icon/make_icon.py` — Pillow-only generator for `assets/icon.ico`. Draws each size (16/32/48/64/128/256) programmatically: rounded-square navy→blue gradient + bold white "M" + a small down-arrow on sizes ≥ 48. No SVG renderer dependency. Rerun (`python tools/make-icon/make_icon.py`) when changing the design; commit the regenerated `.ico`.
- `installer/md-previewer.iss` (+ `installer/README.md`) — Inno Setup 6 script for the per-user Windows installer. Installs to `%LOCALAPPDATA%\Programs\MdPreviewer\` (no admin needed), bundles `target/release/md-previewer.exe` + the entire `assets/` tree + the `samples/` tree (demo Markdown files surfaced via a Start-menu "Sample Documents" shortcut that opens `{app}\samples` in Explorer), creates Start-menu (and optional desktop) shortcuts, and writes opt-in `HKCU` registry entries (ProgID `MdPreviewer.md`, `.md`/`.markdown` association, folder & file context menus) under user-toggleable wizard tasks (`assoc_md`, `ctx_folder`, `ctx_file`, `desktopicon`, `tikz`). The repo-root **`HISTORY.md`** (user-facing per-version release notes, hand-authored & git-tracked — *not* a generated file) is bundled into `{app}` and **auto-opened in the previewer after install**: the `[Run]` launch entry passes `"{app}\HISTORY.md"` as the exe argument and carries the `postinstall skipifsilent` flags, so the wizard's final-page checkbox (checked by default) is the natural opt-out. A `更新履歴 (Release Notes)` Start-menu shortcut re-opens it on demand. The repo-root **`README.md`** (the user-facing guide) and **`LICENSE`** ship the same way: `README.md` gets a `使い方 (README)` Start-menu shortcut plus an **unchecked** `[Run]` postinstall entry, both opening it in the previewer itself. Because it lands at `{app}\README.md` with `{app}\samples\` as a sibling, its `samples/...` relative links resolve and are clickable in the installed app — so keep README links to samples relative. (Its `[LICENSE](LICENSE)` / `[CLAUDE.md](CLAUDE.md)` links stay inert: the cross-file link handler only navigates `.md`/`.markdown`, and `CLAUDE.md` is a dev doc that is deliberately not bundled.) AppId GUID is fixed (`892BC24C-95B0-43BB-8480-087C91AC6316`) so successive versions upgrade in place. `AppVersion` must be bumped in lockstep with `Cargo.toml`'s `version =`. Build: `iscc installer\md-previewer.iss` → `dist\MdPreviewer-Setup-<ver>.exe`. Caveat: if Windows' "Default apps" Settings has an explicit user choice for `.md`, that overrides the HKCU default written by the installer.

  **The TikZ engine is the one asset the installer does NOT ship.** `assets\*` carries `Excludes: "libs\tikzjax\*"`, and a `tikz` wizard task (**on by default**) instead runs a `[Code]` `CurStepChanged(ssPostInstall)` handler that downloads the upstream npm tarball, verifies a pinned SHA-256, and extracts it with Windows' bundled `tar.exe` — `--strip-components=1 package/dist` lands `dist/` exactly where `fetch-libs.ps1` puts it with no move step, and a second pass extracts the tarball's own `LICENSE` (which sits outside `package/dist`). This mirrors `tools/fetch-libs.ps1:152-192`. Rationale and the GPL analysis are in `installer/README.md`. Five things are load-bearing:
  - **Failure is always soft.** No internet, a blocked proxy, a hash mismatch, or a missing `tar.exe` all leave a fully working previewer; only `tikz`/`tikzcd` blocks degrade (see the `__tikzAvailable` gate under *Preview Pipeline*). `SuppressibleMsgBox` shows the notice interactively and silently returns the default under `/VERYSILENT`, which is exactly what the auto-updater path needs.
  - **The `Excludes` is also what makes upgrades safe** — `[Files]` never touches an existing `assets\libs\tikzjax\`, and the handler skips when `dist\tikzjax.js` is already there, so an upgrade neither re-downloads nor deletes. Corollary: bumping `#define TikzjaxVersion` does **not** upgrade an existing install's engine.
  - **Comments in `[Code]` are `//`, not `{ }`.** Pascal brace comments do not nest, so an `{app}` / `{tmp}` constant named inside one ends it early — this is a compile error, and it is easy to reintroduce when editing.
  - **A mirror is supported** for machines that cannot reach npm: `/TIKZSRC=` (+ `/TIKZSHA256=`), then `{app}\assets\tikz-source.ini`, then the compiled-in URL. INI rather than JSON because Inno has `GetIniString` built in and Unicode-safe and no JSON parser at all; `update.json` stays JSON because *its* consumer is Rust/serde. Example: `assets/tikz-source.example.ini`. Note that hosting the tarball makes the host a distributor — fine inside one organisation, not on a public share.
  - **`[UninstallDelete]` removes `{app}\assets\libs\tikzjax`**, since a post-install download is not in the uninstall log and would otherwise be orphaned.

  **The ABC playback sound bank is the second install-time download**, on the same pattern (`abcsound` task, on by default, `Excludes: "libs\abcjs\soundfont\*"`, soft failure, its own `[UninstallDelete]` line) but for a different reason: 88 MP3s compress to nothing, so shipping them would add their full ~2MB to a ~7MB installer. Differences worth knowing:
  - **88 downloads, not one archive** — upstream publishes only individual note files. `AbcSfNotes()` builds the list in Pascal, mirroring `$AbcSoundfontNotes` in `fetch-libs.ps1`; `DownloadTemporaryFile` is called per note inside a `try`, so one unreachable file costs that note's silence rather than the whole bank, and files already present are skipped (upgrade and retry both work).
  - **No SHA pin.** The tikz tarball is hashed because it is a GPL binary fetched once; hashing 88 sample files would be 88 pins to maintain for data whose corruption is audible, not dangerous.
  - **`C8.mp3` is the marker** — fetched last, and the exact file `assets/index.html` probes at runtime, so "installed" means the same thing on both sides.
  - `CurStepChanged` now only dispatches: `InstallTikz()` then `InstallAbcSoundfont()`, each reporting its own soft failure, so a machine that fails one is still offered the other.

### Assets (loaded at runtime)

- `assets/index.html` — preview UI template.
- `assets/editor.html` + `assets/editor.css` — editor window UI template. Loads `assets/libs/editor/editor.iife.js` and calls `window.MdEditor.create(root)`.
- `assets/libs/` — bundled JS/CSS: `marked`, `mermaid`, `katex/`, `highlight.js/`, `hljs-modelica.js` (**in-house**, git-tracked — the Modelica grammar hljs core lacks), `marp/` (Marp Core IIFE), `editor/` (CodeMirror 6 + Vim IIFE), `markwhen/markwhen.iife.js` (`@markwhen/parser` IIFE — `window.Markwhen`, for `markwhen` timeline blocks), `plotly/plotly.min.js` (Plotly.js full dist-min), `js-yaml.min.js` (YAML spec parser for `plotly` blocks), `abcjs/abcjs-basic-min.js` (abcjs — ABC music-notation renderer **and synth** for `abc` blocks; the `basic` build already carries the whole audio stack) plus `abcjs/soundfont/acoustic_grand_piano-mp3/` (88 MP3 note samples, ~2.1MB, **CC-BY-3.0** FluidR3_GM — data, not code, and the thing playback actually needs; present in a dev checkout via `fetch-libs.ps1` but **excluded from the installer** and downloaded at install time by the `abcsound` task, see *Build / installer / icon*), `kataskeve/kataskeve.min.js` ([kataskeve](https://github.com/yvvakimoto/kataskeve) — 2D Euclidean-geometry engine for `kataskeve` blocks; MIT, zero deps, `window.kataskeve`), `kataskeve3d/` ([kataskeve3d](https://github.com/yvvakimoto/kataskeve3d) — 3D pen-and-ink geometry engine for `kataskeve3d` blocks; MIT, zero deps, `window.kataskeve3d`, `kataskeve3d.min.js` + an **optional** `kataskeve3d.wasm` accelerator whose absence costs only speed), `tikzjax/dist/` ([@rod2ik/tikzjax](https://www.npmjs.com/package/@rod2ik/tikzjax) — WASM TeX engine + `core.dump.gz` + Computer-Modern woff2 fonts + `tex_files/*.gz`, for `tikzcd` / `tikz` blocks; **GPL/LPPL**, the only copyleft + only WASM lib — present in a dev checkout via `fetch-libs.ps1`, but **excluded from the installer** and downloaded at install time instead, see *Build / installer / icon*), `feynmark/feynmark.min.js` ([feynmark](https://github.com/yvvakimoto/feynmark) IIFE — `window.feynmark`, MIT, for `feynman` Feynman-diagram blocks; fetched from jsDelivr's GitHub endpoint since it isn't on npm).
- `assets/THIRD_PARTY_LICENSES.txt` — aggregated OSS license texts for every bundled library (direct + transitive npm deps of the `marp/` and `editor/` IIFE bundles). **Git-ignored — generated locally** by `tools/collect-licenses.ps1` (run via `pwsh -File tools/install-deps.ps1 -Licenses` or directly) and required on disk before `iscc` builds the installer. Must be regenerated whenever `tools/build-marp/` or `tools/build-editor/` dependencies change. The file ships through the existing `..\assets\*` recurse in `installer/md-previewer.iss` — no installer change needed. The MIME map in `src/main.rs` (`get_mime_type`) routes `.txt` as `text/plain; charset=utf-8` so WebView2 fetches it inline instead of prompting a download.

Assets are **read at runtime**, not embedded in the binary, so they must be present next to the executable (see *Build & Run Commands* (`CLAUDE.md`) below).

- `tools/install-deps.ps1` — top-level installer. Orchestrates `fetch-libs.ps1` + the three `build-*` projects (`build-marp`, `build-editor`, `build-markwhen`) + (optionally) `collect-licenses.ps1`. Run once after `git clone`. See *Build & Run Commands* for flags.
- `tools/fetch-libs.ps1` — downloads pinned versions of marked, mermaid, KaTeX (JS + CSS + 22 woff2 fonts), highlight.js (JS + github theme CSS), Plotly.js (`plotly.js-dist-min`), js-yaml, abcjs (`abcjs-basic-min.js` plus the 88-note ABC playback sound bank), and the kataskeve / kataskeve3d geometry engines from cdnjs / jsdelivr into `assets/libs/`. **kataskeve / kataskeve3d / feynmark are pinned by git TAG, not npm version** — they are distributed from their GitHub repos (committed `dist/` or `cdn/`, served by `cdn.jsdelivr.net/gh/…`), so the URLs carry the `v` prefix the tags use. kataskeve / kataskeve3d's `.css` files are deliberately **not** fetched: they are container/error chrome only, and `assets/index.html` carries an equivalent ruleset in its first `<style>` because `buildExportArtifact()` inlines only that one (CSS arriving via `<link>` would vanish from every HTML export). feynmark isn't published to npm yet, so `cdn.jsdelivr.net/gh/yvvakimoto/feynmark@v<ver>/cdn/feynmark.min.js` serves a tagged commit of the repo directly (its own `cdn/` build output is committed for exactly this reason). It also pulls **@rod2ik/tikzjax** (for `tikzcd` / `tikz` blocks) — unlike the single-file libs, that ships a ~7.7MB dist tree of 400+ files, so it's fetched as the **npm tarball and extracted** into `assets/libs/tikzjax/dist/` (Windows-bundled `tar`). The ABC sound bank is 88 individual URLs rather than one archive (that is the only format upstream publishes), so it is expanded from `$AbcSoundfontNotes` — the 88 piano keys A0..C8 with **flat** spellings, which is what abcjs asks for; sharps would 404 silently. `C8` is fetched **last** and is therefore the completeness marker both `build.ps1`'s sentinel list and `assets/index.html`'s runtime probe key off. **`$TikzjaxVersion` here and `#define TikzjaxVersion` / `#define TikzjaxSha256` in `installer/md-previewer.iss` are two independent pins that must be kept in sync** — and so are the ABC sound bank's note list + base URL, duplicated in that same `.iss` for the same reason — the `.iss` cannot read this script, and the installer downloads the same tarball itself rather than shipping the extracted tree (see *Build / installer / icon*). Idempotent (skips existing files unless `-Force`). When bumping a pinned version inside this script, also re-run `collect-licenses.ps1` so `assets/THIRD_PARTY_LICENSES.txt` stays in sync. **`.gitignore` policy**: generated artifacts under `assets/libs/` are ignored by *enumerating each one explicitly* (the fetched libs here plus the `marp/` & `editor/` esbuild bundles), so any future hand-written in-house source under `assets/libs/` is **tracked by default** and never silently dropped. When adding a *new* fetched/built library, add its path to `.gitignore` as well.
- `tools/build-marp/` — esbuild project that bundles `@marp-team/marp-core` (which ships only CJS) into the single IIFE at `assets/libs/marp/marp.iife.js`. Run `npm install && npm run build` after bumping the marp-core version. **Output is git-ignored** — regenerate locally via `install-deps.ps1`, do not commit.
- `tools/build-editor/` — esbuild project that bundles CodeMirror 6 + `@replit/codemirror-vim` + the in-tree `mathInputAssist.js` / `charCount.js` / `texEnvComplete.js` / `pathComplete.js` / `fencedDivComplete.js` / `marpSlides.js` / `mdTable.js` / `tablePaste.js` / `mdBlocks.js` / `cells.js` / `editorPrefs.js` / `clipboardSync.js` / `keyLayout.js` (and the other helper modules) into the single IIFE at `assets/libs/editor/editor.iife.js`. Run `npm install && npm run build` to regenerate. Output is git-ignored. Unit tests: `node mdTable.test.mjs`, `node tablePaste.test.mjs`, `node cells.test.mjs`, `node editorPrefs.test.mjs`, `node keyLayout.test.mjs`.
- `tools/build-markwhen/` — esbuild project that bundles [`@markwhen/parser`](https://www.npmjs.com/package/@markwhen/parser) (ESM, with its luxon / yaml / ical.js / rrule deps) into the single IIFE at `assets/libs/markwhen/markwhen.iife.js` (`globalName: 'Markwhen'`). `entry.js` re-exports the parser surface (`parse`, `isEvent`, `ranges`, …) consumed by `renderMarkwhenCached()` for the `markwhen` timeline blocks. Run `npm install && npm run build` after bumping the parser version. Output is git-ignored — regenerate locally via `install-deps.ps1`, do not commit.
- `tools/collect-licenses.ps1` + `tools/license-texts/*.LICENSE` — generator and per-library fallback license bodies. The script prefers each npm package's own `LICENSE`/`COPYING` file under `node_modules/`; for directly bundled libs that have no `node_modules` entry it reads `tools/license-texts/{marked,highlight.js,katex,katex-fonts,mermaid}.LICENSE`. A generic `tools/license-texts/Apache-2.0.LICENSE` is used as a last-resort fallback when an npm dep's `package.json` declares `Apache-2.0` but ships no LICENSE file in the tarball (currently triggered by `mj-context-menu`). The script uses `npm ls --omit=dev --all --parseable` to filter the dep tree down to runtime-only packages, so the bundler (esbuild + its `@esbuild/*` platform subpackages) is excluded — they don't end up in the IIFE artifact.
