# Fenced-block render engines

**Owns:** the fenced-block engines in `assets/index.html` and `assets/libs/{mermaid,katex,plotly,abcjs,markwhen,tikzjax,kataskeve,kataskeve3d,feynmark,highlight.js}`

**Related:** preview-core.md (`awaitLib`, memoization), marp.md (same engines inside slides), export.md

- **Mermaid** — ` ```mermaid ` fenced blocks are intercepted post-`marked.parse()` and substituted with rendered SVG. Mermaid accepts an optional leading `scale: <factor>` directive line (e.g. `scale: 1.5` enlarges to 150% — useful in Marp where mermaid's natural `max-width` makes diagrams feel small on a 1280px slide): `parseMermaidScale()` in `assets/index.html` strips the leading `scale:`/blank lines before `mermaid.render` (mermaid keys off the first line for the diagram type, so the directive must not reach it) and `applyMermaidScale()` post-multiplies the rendered SVG's `style="max-width:Npx"` (mermaid v10 `useMaxWidth:true` output; falls back to the `width`/`height` attributes otherwise). Works in both pipelines since both go through `renderMermaidCached`; the memoization cache key is the full source incl. the `scale:` line, so changing the factor re-renders (see *Diagram render memoization*). **Node-label clipping fix** — `mermaid.initialize` is fed a shared `mermaidBaseConfig()` (used by both `ensureMermaid()` and the `applyDarkMode()` M-key re-init) that sets `fontFamily` to the page's system-sans stack, so mermaid *measures* label text with the same font it *renders* with; without this the `<foreignObject>` HTML labels inherit Segoe UI (taller than mermaid's default measuring font) and the node box is sized too short, clipping the bottom of the glyphs. A CSS safety net (`.mermaid foreignObject { overflow: visible }` + `box-sizing: content-box` on the label `div`/`span`, undoing the global `* { box-sizing: border-box }`) guards against any residual overflow.

- **CSV / TSV codeblocks** — fenced ` ```csv ` / ` ```tsv ` render as HTML `<table>` (first row → `<thead>`). CSV parsing follows RFC 4180 (quoted fields may contain commas, newlines, and `""` for a literal quote); TSV splits each line on `\t` with no quoting. Fully-empty rows (blank lines anywhere in the source — leading, between header and body, or trailing) are dropped before the first row is assigned to `<thead>`, so authors can add visual whitespace inside the fence without producing a stray empty `<tr>`. Output wraps the table in `<div class="csv-table">` and inherits each theme's existing table styling. Carries through to HTML export since the live `<table>` DOM is serialized.

- **Plotly charts from external CSV/TSV** — fenced ` ```plotly ` blocks contain a YAML spec referencing an external `.csv` / `.tsv` file (path relative to the `.md`), plus chart-type and column directives. The CSV is fetched via the existing `app://localhost/userfile/...` route (the new `csv` / `tsv` MIME registrations in `get_mime_type` ensure `text/csv; charset=utf-8` / `text/tab-separated-values; charset=utf-8`), parsed with the same `parseCsv()` used by `csv` tables, then handed to `Plotly.newPlot`. Supported `type:` values: `line`, `scatter`, `bar`, `histogram`, `box`, `heatmap`, `surface` (the last two read the CSV as a matrix — row 0 → x labels, col 0 → y labels, remaining cells → z). `y:` may be a list for multiple series; full multi-trace control is also available via a `traces:` list whose `x:`/`y:`/`z:` strings are resolved as CSV column names. Optional `layout:` / `config:` blocks deep-merge into Plotly's layout/config. Plotly.js + js-yaml are lazy-loaded (`ensurePlotly()` / `ensureJsYaml()`) so docs without `plotly` blocks pay no startup cost. **Live reload on external CSV change**: each block posts a `csvwatch:<relpath>` IPC to the Rust host on render, which adds the resolved absolute path to a `watched_csvs: Arc<Mutex<HashSet<PathBuf>>>` and (in single-file mode) calls `watcher.watch()` on it; a `csvwatchreset:` IPC at the start of every render flushes the prior set so only files of the current document are tracked. The notify event handler re-renders the active `.md` when any tracked CSV is modified. Errors (missing `file:`, fetch failure, parse failure, invalid `type:`, missing column) render as a `.plotly-error` red-bordered block in place; other charts on the same page remain unaffected. Carries into Marp slides (separate branch in the Marp `code[class*="language-"]` substitution loop; the `.plotly-block` is a *figure* participant so it is horizontally centered like the other figures via the `.marp-fig` class — see *Marp Mode → Figure horizontal centering*). HTML export snapshots each block's `__plotlySpec` ({traces, layout, config}) onto a `data-plotly-spec` attribute, references Plotly.js via `cdn.jsdelivr.net` (`EXPORT_PLOTLY_JS_CDN`), and ships an inline `initPlotlyArtifact()` that re-runs `Plotly.newPlot` on each block once the deferred CDN script has loaded — so the artifact retains zoom / hover / pan interactivity when hosted on a static server.

- **ABC music notation** — fenced ` ```abc ` blocks contain [ABC notation](https://abcnotation.com/) (the plain-text music notation format) and are rendered as an inline staff SVG via the bundled [`abcjs`](https://github.com/paulrosen/abcjs) (`assets/libs/abcjs/abcjs-basic-min.js`, MIT, lazy-loaded by `ensureAbcjs()` the first time an `abc` block appears). **Render-only — no MIDI/audio playback.** Post-`marked.parse()` the block is replaced with `<div class="abc-notation" data-abc="1" data-abc-source="…">`; `renderAbcCached()` then calls `ABCJS.renderAbc(el, src, { staffwidth: 740, … })` into it. **abcjs emits the `<svg>` with fixed `width`/`height` attributes but no `viewBox`**, so `.abc-notation svg { max-width:100% }` shrinks the SVG *box* while its content stays drawn at absolute `0..width` coordinates — i.e. inside a narrow container (notably a Marp split column, ~245–535px wide) the staff is **clipped on both axes, not scaled**. To fix this `renderAbcCached()` post-processes the rendered SVG: it adds `viewBox="0 0 <w> <h>"` (from the intrinsic `width`/`height`), sets `preserveAspectRatio="xMidYMid meet"`, sets `width="100%"`, caps `style.max-width` at the intrinsic width (so it never upscales beyond native in a wide container), and drops the `height` attribute so the viewBox ratio drives `height:auto`. The result is a responsive SVG that scales-to-fit any container width purely via CSS — **no width measurement**, and correct even when rendered while the slide is `display:none` (e.g. a non-active deck slide), since the cached innerHTML already holds the responsive SVG. This manual viewBox is preferred over abcjs's `responsive:'resize'` (which leaks a window listener that is lost on cached-innerHTML re-insert). Output is pure inline SVG so HTML export carries through with no special snapshot handling. Dark mode recolors the monochrome SVG via CSS (`body.dark-mode .abc-notation svg path/text/rect/line { fill/stroke }`), so the rendered bytes are theme-independent (the memoization cache is therefore un-salted — keyed by the raw source; see *Diagram render memoization*). Errors render as an `.abc-error` red-bordered block in place; other blocks are unaffected. Carries into Marp slides via the same `code[class*="language-"]` substitution loop, and `.abc-notation` is included in the Marp `.marp-fig` figure detection (horizontal centering). Sample: `samples/abcjs.md`.

- **Markwhen timelines** — fenced ` ```markwhen ` blocks contain [markwhen](https://markwhen.com/) text (a markdown-like timeline DSL) and are rendered as a **horizontal cascading timeline** (custom inline-SVG renderer; no iframe / Vue view). The bundled [`@markwhen/parser`](https://www.npmjs.com/package/@markwhen/parser) (esbuild IIFE at `assets/libs/markwhen/markwhen.iife.js`, exposing `window.Markwhen`, lazy-loaded by `ensureMarkwhen()` the first time a `markwhen` block appears) does all the date work — `parse(src)` returns a single timeline whose `events` tree resolves every event's `dateRangeIso.fromDateTimeIso` / `.toDateTimeIso` to absolute ISO strings, so the renderer needs **no runtime date library** (`Date.parse` only). Post-`marked.parse()` the block is replaced with `<div class="markwhen-timeline" data-markwhen-source="…">`; `renderMarkwhenCached(el)` in `assets/index.html` then: walks the `events` tree (`Markwhen.isEvent()` distinguishes an `Event` from an `EventGroup`), flattening it into rows — each `EventGroup` with a non-empty `title` emits an indented section label and bumps the depth; each `Event` emits a row using `firstLine.restTrimmed` as its label; gets the overall span from `Markwhen.ranges(root, [])` (`{fromDateTime,toDateTime}`, falling back to scanning events); picks axis tick granularity (years > ~3y span, else months, else day-ish); and emits one responsive `<svg>` (`viewBox` + `width:100%`/`height:auto`) with gridlines + a time axis, one row per item, **range events as bars / single-date events as dots**, positioned by date. Tag color comes from the markwhen header (`#tag: color` lines — the parser escapes the leading `#` to `)`, so the lookup is `header[")"+tag]`, validated with `CSS.supports('color', …)`), else a stable hashed palette color; light/dark palettes are chosen at render time. Memoized via `__markwhenCache` keyed by `__diagKey(src)` (theme-salted, since concrete colors are baked into the SVG — see *Diagram render memoization*). Errors render as a `.markwhen-error` red-bordered block in place; other blocks are unaffected. Output is pure inline SVG so **HTML export carries through with no special snapshot handling**, and it works in **Marp** via the same `code[class*="language-"]` substitution loop (`.markwhen-timeline` is included in the `.marp-fig` figure detection so a timeline on a non-split slide is horizontally centered). Built by `tools/build-markwhen/` (see *Architecture → Tools*). Sample: `samples/markwhen.md`.

  - **Calendar view (`display: calendar`) + online holidays** — adding `display: calendar` (or the boolean alias `calendar: true`) to the markwhen **header** switches the same data to a **month-grid calendar** SVG instead of the timeline. **`view` is NOT usable** — it's a reserved markwhen header key that the parser mangles (`view: calendar` → an empty array), whereas non-reserved keys like `display` / `calendar` / `country` are preserved verbatim, so the trigger reads `mw.header.display === 'calendar'` / `mw.header.calendar === true`; anything else keeps the timeline. `renderMarkwhenCached` is therefore **`async`**, and the two render loops (normal + Marp) now `await Promise.all(...)` over the blocks (mirroring the plotly loop) so the finished DOM — with holidays — is in place before `__emitRenderDone`, i.e. before HTML export / `--export-png` capture snapshots it. The shared parse/flatten/timeline logic was extracted into `__mwFlatten()` / `__mwBuildTimeline()`; the calendar is built by **`__mwBuildCalendar(mw, events, holidays)`**, which renders **consecutive month grids from the first event's month to the last** (single-day events → chips, multi-day ranges → week-spanning bars, packed into per-week lanes FullCalendar-style with a `+N` overflow indicator, a tag→color legend, JP weekday headers with Sun/Sat coloring). Very wide spans fall back to the timeline with a `.markwhen-note`: the `__MW_CAL_MAX_MONTHS = 36` cap guards against a decade-spanning history producing hundreds of grids. **Holidays are online-only** (`navigator.onLine`-gated) so the offline-by-design guarantee holds: `__mwFetchHolidays(country, years)` fetches from **nager.at** (`https://date.nager.at/api/v3/PublicHolidays/{year}/{country}`, free/keyless/CORS-`*`; `date` is already `YYYY-MM-DD`, `localName` is the local-language name — Japanese for JP) with an `AbortController` timeout (`__MW_HOLIDAY_TIMEOUT_MS = 4000`), caches per `(country, year)` in `__mwHolidayCache`, and **swallows all failures** (offline/network/timeout/bad-JSON) → no holidays, no error, normal render. Default country is **JP**, overridable via a `country:` header key. Holiday cells get a distinct accent fill + the holiday name; the day number recolors. Calendar renders are memoized in a **separate `__markwhenCalCache`** keyed by `` `${__diagKey(src)}|cal|${country}|${online?'on':'off'}` `` so an offline→online transition (holidays appear) correctly re-renders. Colors are baked into the SVG (theme-salted, like the timeline), so export / Marp carry the calendar — and any online-fetched holidays — through unchanged. Sample: the `display: calendar` block in `samples/markwhen.md`.

- **tikz-cd commutative diagrams (` ```tikzcd `) + general TikZ (` ```tikz `)** — fenced blocks are rendered to **inline SVG by a WASM TeX engine**, [@rod2ik/tikzjax](https://www.npmjs.com/package/@rod2ik/tikzjax) (`assets/libs/tikzjax/dist/`, ~7.7MB: `tikzjax.js` orchestrator + `run-tex.js` engine + `tex.wasm.gz` + `core.dump.gz` + `fonts/*.woff2` + on-demand `tex_files/*.gz`). This is the project's **first WebAssembly** dependency and **first copyleft (GPL/LPPL)** dependency; it's **fully offline** and **lazy-loaded** by `ensureTikz()` only when a `tikz`/`tikzcd` block appears (docs without one pay nothing). `ensureTikz()` sets `window.TikzJaxOptions.assetBaseUrl` to an **absolute** URL (`new URL('libs/tikzjax/dist', document.baseURI)`) — the TeX engine runs in a blob **Web Worker** whose base URL is opaque, so a relative base can't resolve the on-demand `tex_files/*.gz` fetches (they'd 404 and break package loads like tikz-cd) — and injects a `<link>` to `fonts.css` (glyphs are PUA-mapped `<text>` in the Computer-Modern web fonts, not embedded paths). Post-`marked.parse()` each block becomes `<div class="tikzcd-diagram|tikz-diagram" data-tikz-kind="cd|raw" data-tikz-source="…">`; **`renderTikzCached(el)`** injects a `<script type="text/tikz">` (auto-wrapping a `tikzcd` body in `\begin{tikzcd}…\end{tikzcd}` with `data-tex-packages='{"tikz-cd":"","amssymb":""}"`; the body is **whitespace-trimmed** because a blank line inside a tikzcd matrix becomes a `\par` → the cryptic "Missing $ inserted") which tikzjax's `document.body` `MutationObserver` auto-compiles in the worker; `__tikzAwait(el)` resolves when the wrapper drops its `tikzjax-loading` class (success **or** a broken-image failure — no 30s wait) or on a 30s timeout, then the finished `el.innerHTML` is memoized. **Diagrams render small, so they're enlarged by default** — `__applyTikzScale()` multiplies the finished SVG's intrinsic `width`/`height` (its `viewBox` drives clean scaling; `max-width:100%` still caps an oversize result) by `__TIKZ_SCALE = 1.6`, overridable per block with a leading `scale: <n>` directive line (stripped before the TeX body, mirroring mermaid's `scale:`; the full source incl. that line keys the cache). **NOTE** some diagrams (curved/diagonal arrows) contain a dvisvgm-emitted *nested* `<svg>` inside the outer one — `__applyTikzScale` scales the **outer** wrapper svg only, so the whole figure scales together. Cache **`__tikzCache`** is un-salted (keyed by `kind+source`, like abc) because the SVG uses `stroke/fill=currentColor` → **dark mode is a CSS `color` change** (`body.dark-mode .tikzcd-diagram .tikzjax-wrapper { color:#d0d0d0 !important }` overrides tikzjax's inline black). A failed compile (tikzjax's `.tikzjax-broken-wrapper`/`.tikzjax-broken-image`) is replaced with a styled `.tikz-error` block. **Rendering is fire-and-forget (NOT awaited before `__emitRenderDone`)** — a TeX compile takes seconds and a bad diagram waits out the 30s timeout, so awaiting it would freeze the "読み込み中" splash (hidden only after `renderMarkdown` resolves); each block shows a "コンパイル中…" placeholder and fills in async. Wired into **both** pipelines (Marp uses the same `renderTikzCached`; `.tikzcd-diagram`/`.tikz-diagram` are in the `.marp-fig` figure-centering set). **HTML export**: the inline SVG carries through the cloned DOM, but glyphs need the CM fonts — so `buildExportArtifact()` collects the `font-family` values used across tikz SVGs and inlines just those `libs/tikzjax/dist/fonts/<name>.woff2` as base64 `@font-face` (else PUA glyphs render as blank tofu). **`--export-png` does NOT capture tikz** — the headless hidden window can't run the wasm Web Worker (documented limitation; awaiting would hang, which is another reason rendering is fire-and-forget). `src/main.rs` `get_mime_type` gained `Some("wasm") => "application/wasm"` (the `.gz` assets stay `application/octet-stream` and are decompressed in JS). Fetched (as an extracted npm tarball) by `tools/fetch-libs.ps1`. **NOT shipped in the installer** — it is GPL-3.0-or-later with LPPL TeX packages and compiled WASM binaries, and conveying a compiled GPL binary would oblige us to offer its Corresponding Source; an opt-in installer task downloads it from the npm registry at install time instead, so the product never conveys it (see *Architecture → Build / installer / icon*). Consequently **the engine may legitimately be absent at runtime**, and that is a first-class state rather than a fault: `src/main.rs` probes `assets/libs/tikzjax/dist/tikzjax.js` next to the other init-script globals and injects **`window.__tikzAvailable`**, which `assets/index.html` reads through **`__tikzUnavailable()`**. **Undefined means available** — `tools/preview-harness/serve.py` injects the other host globals but not this one, so the flag may only ever *suppress*, never enable; inverting that would silently kill tikz for every harness run. When it is false, `ensureTikz()` rejects immediately (no `<script>` is injected that could only 404) and both pipelines swap in **`__tikzUnavailableHtml()`**, which distinguishes *never installed* (actionable: re-run the installer and tick the box) from *installed but failed to load* (a real fault). The protocol handler's 404 `dbg_log!` gate also covers `/libs/` so an absent engine is diagnosable from `md-previewer.log`. Sample: `samples/tikzcd.md` and the 可換図式 slide in `samples/marp.md`.

- **Kataskeve geometry diagrams (` ```kataskeve ` 2D + ` ```kataskeve3d ` 3D)** — two independent MIT, zero-dependency engines bundled from their GitHub repos ([kataskeve](https://github.com/yvvakimoto/kataskeve) 0.1.1 / [kataskeve3d](https://github.com/yvvakimoto/kataskeve3d) 0.1.0), lazy-loaded by `ensureKataskeve()` / `ensureKataskeve3d()` so docs without a block pay nothing. **Both loaders must call `initialize({ startOnLoad: false, injectStyles: false })`**: each bundle schedules its own mermaid-style auto-init with `setTimeout(boot, 0)`, which would scan `.kataskeve, pre code.language-kataskeve` and stamp `data-…-processed` on our still-empty host divs — `loadLib` resolves inside the script's `onload` *task*, so the `await` continuation is a microtask of that task and provably beats the timeout. `injectStyles:false` because the app owns the CSS: `buildExportArtifact()` inlines only the document's **first** `<style>`, so a library-injected (or `<link>`ed) ruleset would silently vanish from every HTML export — which is also why neither package's `.css` is fetched at all (both are container/error chrome only). **The two engines are opposites in almost every respect, and those differences are the design:** (1) *output* — 2D `render(src)` is a **pure string→string** call returning a complete inline `<svg>`, so it caches, exports and Marp-embeds like mermaid; 3D `renderElement(src, host)` **rasterizes into a `<canvas>` and wipes the host**, and there is no string-returning API. (2) *caching* — see *Diagram render memoization*; the 3D path is the one place `__diagCacheHit` is forbidden. (3) *errors* — **neither engine throws**; both produce an English `<div class="kataskeve[3d]-error">Kataskeve[3D] error: …</div>`, so the failure signal is that class, not an exception, and `__ksLocalizeError()` swaps the engine's prefix for `t('err.prefix', {engine})` while keeping the upstream message body. Errors are **not cached**, so a half-typed diagram recovers on the next keystroke and a `setUiLang()` re-render cannot serve a stale-language prefix. (4) *theme* — 2D paints in `currentColor` except the optional grid/axis colours, which the engine picks from **`body.dark-mode`** (this app's own convention, so it works for free); 3D takes its ink from `getComputedStyle(host).color`, which means **the host must be attached to the document** — on a detached node Chromium returns an empty colour and the ink silently falls back to a dark `#1a1a1a`, invisible in dark mode. `display:none` is fine (a computed colour still resolves), which is why a Marp deck's slide 2 renders correctly. (5) *export* — 2D needs nothing; 3D gets a rasterization pass (see *Export*). **No `viewBox` surgery is needed for the 2D SVG** (unlike `renderAbcCached`): kataskeve already emits one, so the element has an intrinsic ratio and `max-width:100%` *scales* rather than clips inside a narrow Marp split column — verified in the split-column slide of `samples/marp.md`. **`penrose_triangle` walks ancestors for the first opaque `background-color` to use as "paper" and defaults to WHITE**; it finds `#preview-container` (white / `#0d1117`) and in Marp the slide `<section>`, so **no background rule was added** — measured, the dark render paints zero opaque-white pixels. **Both renders are `await`ed** in both pipelines (unlike tikz's fire-and-forget): they are synchronous CPU work with no worker, and `--export-png` only captures what landed before `__emitRenderDone`. The await is written `xReady || ensureX()` inside a `try/catch` falling back to `__ksFailAll()`, because a **tilde fence** (`~~~kataskeve`) becomes `class="language-kataskeve"` from marked — hence a host div — but escapes the ```-anchored `needsX` regex, so the bare `if (xReady) await xReady` idiom would let a `TypeError` abort the entire render past pagination, the TOC and `__emitRenderDone` (hanging `--export-png` and leaving the splash up). That hazard pre-exists for abc / plotly / markwhen and is deliberately left alone there. **Fence disambiguation is safe at every site but for a different reason at each**, and each is commented: the normal pipeline's `html.replace` patterns are disjoint because the closing `"` is inside them (`language-kataskeve"` cannot match `language-kataskeve3d"` — the same guarantee the tikz/tikzcd pair already relies on); Marp's `lang === 'kataskeve'` is exact equality over a token captured by `language-([A-Za-z0-9_+-]+)`, which includes digits; `needsKataskeve` is `/```kataskeve(?!3d)\b/` where the `\b` **alone** already suffices (`e`→`3` is a word→word transition, so no boundary exists there) — the lookahead is spelled out only because this is the exact opposite of `/```tikz(cd)?\b/`, which matches both fences on purpose; and `[data-kataskeve]` does not match `data-kataskeve3d` because attribute-presence selectors are exact-name (do **not** "simplify" that to `*=` or `^=`). **No Rust change was needed**: `get_mime_type` already serves `.wasm`, assets are read off disk, and the installer ships `assets\*` recursively (only `libs\tikzjax\*` is excluded) — unlike tikzjax these are MIT, so they are bundled normally and need no `__tikzAvailable`-style availability gate. Samples: `samples/kataskeve.md`, `samples/kataskeve3d.md`, and the two Kataskeve slides in `samples/marp.md`.

- **Feynman diagrams (` ```feynman `) via feynmark** — fenced ` ```feynman ` blocks contain a declarative, Mermaid-style DSL ([feynmark](https://github.com/yvvakimoto/feynmark), MIT — the same author as this project; bundled as a single IIFE at `assets/libs/feynmark/feynmark.min.js`, lazy-loaded by `ensureFeynmark()` the first time a `feynman` block appears) for particle-physics Feynman diagrams: one or more `diagram { ... }` / `equation { ... }` statements per fence, with declarative propagator styles (`fermion`, `photon`, `gluon`, `scalar`, `ghost`, `boson`, `double`, `majorana`, `graviton`, …), edge/vertex attributes (`label`, `momentum`, `bend`, `color`, `dot`/`blob`/`cross`, `at (x,y)`), hadron `brace` brackets, and `equation` blocks that embed `@diagramName` as inline terms in a KaTeX-rendered formula. Layout (external legs pinned to the borders, internal vertices minimizing a spring-tension objective — the feynMF algorithm) and rendering are entirely feynmark's own; md_previewer only drives it, exactly matching the mermaid-style facade convention feynmark's own `render`/`renderInto`/`run`/`initialize`/`config` API already provides — **no `tools/build-feynmark/` esbuild wrapper was needed**, the pre-built, already-committed `cdn/feynmark.min.js` is vendored directly by `tools/fetch-libs.ps1` from jsDelivr's GitHub endpoint (feynmark isn't on npm yet, so this fetches a tagged commit of the repo rather than the `/npm/` endpoint the other CDN-fetched libs use). Post-`marked.parse()` each block becomes `<div class="feynman-block" data-feynman-source="…">`; **`renderFeynmarkCached(root)`** loops its `.feynman-block` elements synchronously (like `renderAbcCached`, not `Promise.all` — feynmark's `render`/`renderInto` are synchronous, no async compile step) and calls `window.feynmark.renderInto(el, src)` directly rather than feynmark's own `run()`, because `run()`'s built-in error-box handling isn't reachable from a direct `renderInto` call — `renderInto()` throws synchronously on a parse/layout/unknown-`@ref` error, so md_previewer wraps it itself and builds its own error box (escaping `FeynmarkError.excerpt()`, which returns plain text). **Class names deliberately use `feynman` (no "k")** — `.feynman-block` (the outer per-fence container) / `.feynman-error` (md_previewer's own error box) — to avoid colliding with feynmark's own internal wrapper classes (`.feynmark-diagram` per un-referenced diagram, `.feynmark-equation` per equation, root `<svg class="feynmark">`, its own unused `.feynmark-error`). feynmark renders with `stroke/fill: currentColor` (verified in its `render/theme.ts`), so — like `abc`/`tikz`, unlike `mermaid`/`markwhen` — **dark mode needs no re-render and the memoization cache (`__feynmarkCache`) needs no theme salt**, keyed by the raw source directly (see *Diagram render memoization*). feynmark optionally uses **KaTeX** (already bundled, lazy-loaded the same way) for math labels and `equation`/`@name` embedding — it never imports KaTeX itself, resolving `window.katex` at render time and falling back to plain text if absent — so md_previewer's `needsFeynman` gate awaits `Promise.all([ensureFeynmark(), ensureKatex()])` regardless of whether the document's own `$...$` math is present. `@name` references only resolve against diagrams defined earlier in the *same* `renderInto()` call, so the entire fence is always rendered as one source string into one container div (never split per-diagram), mirroring the markwhen/abc/tikz "one fence, one div" convention. Works in both pipelines (`.feynman-block` is in the Marp `.marp-fig` figure-centering set and the `::: vcenter` reset); output is pure inline SVG (+ `<foreignObject>` KaTeX for equations) so **HTML export carries through with no special snapshot handling**, same as markwhen/abc. No Rust changes. Sample: `samples/feynman.md` and the フェインマン図 slide in `samples/marp.md`.

- **KaTeX math** — `$...$` and `$$...$$` are extracted via `extractMathInto` placeholder pass *before* `marked.parse` and rendered as pre-rendered spans afterward. Same placeholder pass runs on footnote bodies so footnote math, tooltips, and exported artifacts all share the same KaTeX output. `renderMathExpressions()` renders with **`output: 'htmlAndMathml'`** (not html-only) so each expression carries a hidden `<span class="katex-mathml"><math>…</math></span>` whose `<semantics>` includes an `<annotation encoding="application/x-tex">` with the original LaTeX. This powers **`setupMathContextMenu()`** in `assets/index.html`: a single delegated `contextmenu` listener on the stable `#preview` element (wired once, guarded by `__mathMenuWired`, so it survives the per-render `innerHTML` rebuild) shows a right-click **"Copy MathML / Copy LaTeX"** menu on any `.katex` element — MathML via `XMLSerializer` on the `<math>`, LaTeX from the `x-tex` annotation; a format absent from the DOM (e.g. an html-only `.katex`) is shown disabled. Right-clicking outside math falls through to WebView2's native menu (back/forward navigation). Works in both pipelines (Marp's marp-core KaTeX also emits MathML). Copy uses the shared **`copyTextViaTextarea()`** helper (the WebView2-safe `execCommand('copy')` fallback, also used by the code-block copy button). The MathML now also rides into exported HTML, harmlessly improving accessibility.

- **Syntax highlighting** — `highlight.js` colors code blocks; every block gets a copy button. The bundled `highlight.min.js` is the **common** build, so a language outside that set needs its own grammar module loaded after it. **Modelica** (` ```modelica `, aliases `mo` / `mos`) is provided that way by **`assets/libs/hljs-modelica.js`**, an **in-house, hand-written, git-tracked** definition (a `<script>` in `index.html` right after `highlight.min.js`; it self-registers via `hljs.registerLanguage`). It is hand-written rather than fetched by `tools/fetch-libs.ps1` for two reasons: highlight.js core ships **no** Modelica grammar (absent from the cdnjs / jsdelivr `languages/` set for 11.x), and the npm plugin `highlightjs-modelica` targets hljs v9/v10 — its `contains` ends in `hljs.METHOD_GUARD`, which **v11 removed**, so compiling it against the bundled 11.9.0 throws; it also treats `'...'` as a string when in Modelica single quotes delimit a **quoted identifier (Q-IDENT)**, and files `extends` / `partial` / `within` under built-ins. Two details of the grammar are load-bearing: the string mode is **not** `hljs.QUOTE_STRING_MODE` (that sets `illegal: \n`, but a Modelica documentation / annotation string may span lines), and the two multi-class `begin: [...]` rules that name a class carry negative lookaheads in their third group — `(?!(?:record|function)\b)` so `operator record Complex` names `Complex` rather than `record`, and `(?!(?:if|for|when|while)\b)` so `end when;` stays two keywords instead of tagging `when` as a class name. Being in-house it needs **no `THIRD_PARTY_LICENSES.txt` entry**, and it is **not** covered by the `.gitignore` enumeration of generated `assets/libs/` artifacts, so it is tracked by default. Registration is global, so it serves the normal pipeline and the Marp code-block re-highlight pass alike; HTML export needs nothing (the spans are already in the serialized DOM). Sample: the *Modelica* section in `samples/syntax.md`.
