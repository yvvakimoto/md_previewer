# Fenced-block render engines

**Owns:** the fenced-block engines in `assets/index.html` and `assets/libs/{mermaid,katex,plotly,abcjs,markwhen,tikzjax,kataskeve,kataskeve3d,feynmark,three,highlight.js}`
**Read before:** adding or fixing a fenced-block engine.
**Related:** preview-core.md (`awaitLib`, memoization), marp.md (same engines inside slides), export.md

- **Mermaid** — ` ```mermaid ` fenced blocks are intercepted post-`marked.parse()` and substituted with rendered SVG. Mermaid accepts an optional leading `scale: <factor>` directive line (e.g. `scale: 1.5` enlarges to 150% — useful in Marp where mermaid's natural `max-width` makes diagrams feel small on a 1280px slide): `parseMermaidScale()` in `assets/index.html` strips the leading `scale:`/blank lines before `mermaid.render` (mermaid keys off the first line for the diagram type, so the directive must not reach it) and `applyMermaidScale()` post-multiplies the rendered SVG's `style="max-width:Npx"` (mermaid v10 `useMaxWidth:true` output; falls back to the `width`/`height` attributes otherwise). Works in both pipelines since both go through `renderMermaidCached`; the memoization cache key is the full source incl. the `scale:` line, so changing the factor re-renders (see *Diagram render memoization* (`preview-core.md`)). **Node-label clipping fix** — `mermaid.initialize` is fed a shared `mermaidBaseConfig()` (used by both `ensureMermaid()` and the `applyDarkMode()` M-key re-init) that sets `fontFamily` to the page's system-sans stack, so mermaid *measures* label text with the same font it *renders* with; without this the `<foreignObject>` HTML labels inherit Segoe UI (taller than mermaid's default measuring font) and the node box is sized too short, clipping the bottom of the glyphs. A CSS safety net (`.mermaid foreignObject { overflow: visible }` + `box-sizing: content-box` on the label `div`/`span`, undoing the global `* { box-sizing: border-box }`) guards against any residual overflow.

- **CSV / TSV codeblocks** — fenced ` ```csv ` / ` ```tsv ` render as HTML `<table>` (first row → `<thead>`). CSV parsing follows RFC 4180 (quoted fields may contain commas, newlines, and `""` for a literal quote); TSV splits each line on `\t` with no quoting. Fully-empty rows (blank lines anywhere in the source — leading, between header and body, or trailing) are dropped before the first row is assigned to `<thead>`, so authors can add visual whitespace inside the fence without producing a stray empty `<tr>`. Output wraps the table in `<div class="csv-table">` and inherits each theme's existing table styling. Carries through to HTML export since the live `<table>` DOM is serialized.

- **Plotly charts from external CSV/TSV** — fenced ` ```plotly ` blocks contain a YAML spec referencing an external `.csv` / `.tsv` file (path relative to the `.md`), plus chart-type and column directives. The CSV is fetched via the existing `app://localhost/userfile/...` route (the new `csv` / `tsv` MIME registrations in `get_mime_type` ensure `text/csv; charset=utf-8` / `text/tab-separated-values; charset=utf-8`), parsed with the same `parseCsv()` used by `csv` tables, then handed to `Plotly.newPlot`. Supported `type:` values: `line`, `scatter`, `bar`, `histogram`, `box`, `heatmap`, `surface` (the last two read the CSV as a matrix — row 0 → x labels, col 0 → y labels, remaining cells → z). `y:` may be a list for multiple series; full multi-trace control is also available via a `traces:` list whose `x:`/`y:`/`z:` strings are resolved as CSV column names. Optional `layout:` / `config:` blocks deep-merge into Plotly's layout/config. Plotly.js + js-yaml are lazy-loaded (`ensurePlotly()` / `ensureJsYaml()`) so docs without `plotly` blocks pay no startup cost. **Live reload on external CSV change**: each block posts a `csvwatch:<relpath>` IPC to the Rust host on render, which adds the resolved absolute path to a `watched_csvs: Arc<Mutex<HashSet<PathBuf>>>` and (in single-file mode) calls `watcher.watch()` on it; a `csvwatchreset:` IPC at the start of every render flushes the prior set so only files of the current document are tracked. The notify event handler re-renders the active `.md` when any tracked CSV is modified. Errors (missing `file:`, fetch failure, parse failure, invalid `type:`, missing column) render as a `.plotly-error` red-bordered block in place; other charts on the same page remain unaffected. Carries into Marp slides (separate branch in the Marp `code[class*="language-"]` substitution loop; the `.plotly-block` is a *figure* participant so it is horizontally centered like the other figures via the `.marp-fig` class — see *Marp Mode → Figure horizontal centering* (`marp.md`)). HTML export snapshots each block's `__plotlySpec` ({traces, layout, config}) onto a `data-plotly-spec` attribute, references Plotly.js via `cdn.jsdelivr.net` (`EXPORT_PLOTLY_JS_CDN`), and ships an inline `initPlotlyArtifact()` that re-runs `Plotly.newPlot` on each block once the deferred CDN script has loaded — so the artifact retains zoom / hover / pan interactivity when hosted on a static server.

- **ABC music notation** — fenced ` ```abc ` blocks contain [ABC notation](https://abcnotation.com/) (the plain-text music notation format) and are rendered as an inline staff SVG via the bundled [`abcjs`](https://github.com/paulrosen/abcjs) (`assets/libs/abcjs/abcjs-basic-min.js`, MIT, lazy-loaded by `ensureAbcjs()` the first time an `abc` block appears). Post-`marked.parse()` the block is replaced with `<div class="abc-notation" data-abc="1" data-abc-source="…">`; `renderAbcCached()` gives it a `<div class="abc-staff">` child and calls `ABCJS.renderAbc(staff, src, { staffwidth: 740, … })` into that. **The staff is a wrapper, not the block itself**, so the playback bar added afterwards survives both the memoized `el.innerHTML = cached` restore and the re-render playback performs. abcjs is handed a **throwaway child** to draw into and the result is then MOVED up into the staff (`__abcRenderStaff`): abcjs stamps `overflow:hidden` plus the tune's intrinsic height onto its target and, on the session's first render, comes back asynchronously to clear them again — none of which is part of the memoized innerHTML, so a directly rendered staff would not be byte-identical to a cache-restored one (`keycheck.py` asserts exactly that). Moving rather than cloning keeps the visualObj's element references — which playback highlights through — valid. **abcjs emits the `<svg>` with fixed `width`/`height` attributes but no `viewBox`**, so `.abc-notation svg { max-width:100% }` shrinks the SVG *box* while its content stays drawn at absolute `0..width` coordinates — i.e. inside a narrow container (notably a Marp split column, ~245–535px wide) the staff is **clipped on both axes, not scaled**. To fix this `renderAbcCached()` post-processes the rendered SVG: it adds `viewBox="0 0 <w> <h>"` (from the intrinsic `width`/`height`), sets `preserveAspectRatio="xMidYMid meet"`, sets `width="100%"`, caps `style.max-width` at the intrinsic width (so it never upscales beyond native in a wide container), and drops the `height` attribute so the viewBox ratio drives `height:auto`. The result is a responsive SVG that scales-to-fit any container width purely via CSS — **no width measurement**, and correct even when rendered while the slide is `display:none` (e.g. a non-active deck slide), since the cached innerHTML already holds the responsive SVG. This manual viewBox is preferred over abcjs's `responsive:'resize'` (which leaks a window listener that is lost on cached-innerHTML re-insert). Output is pure inline SVG so HTML export carries through with no special snapshot handling (the playback bar is stripped — see below). Dark mode recolors the monochrome SVG via CSS (`body.dark-mode .abc-notation svg path/text/rect/line { fill/stroke }`), so the rendered bytes are theme-independent (the memoization cache is therefore un-salted — keyed by the raw source; see *Diagram render memoization* (`preview-core.md`)). Errors render as an `.abc-error` red-bordered block in place; other blocks are unaffected. Carries into Marp slides via the same `code[class*="language-"]` substitution loop, and `.abc-notation` is included in the Marp `.marp-fig` figure detection (horizontal centering). Sample: `samples/abcjs.md`.

- **ABC playback** — every rendered staff gets an `.abc-audio-bar` (play/pause, stop, a click-to-seek progress track, elapsed/total time, tempo) built by `addAbcAudioBars(root)`, an idempotent post-pass called right after `renderAbcCached()` in **both** pipelines. It follows `addTableCopyButtons()`'s shape rather than event delegation: `#preview` is rebuilt by `innerHTML` on every render, so the bar is simply re-created, and labels come from `t()` at build time (`applyI18n` never walks `#preview`). Audio is abcjs' own synth (`ABCJS.synth.CreateSynth` + `ABCJS.TimingCallbacks`) rather than `SynthController`, so the chrome obeys the app's dark mode and ja/en toggle and needs no `abcjs-audio.css`.
  - **Sound bank.** abcjs fetches one MP3 per sounding note from `<soundFontUrl><instrument>-mp3/<note>.mp3`, and its built-in default is a CDN — so `soundFontUrl` is **always** passed explicitly (`libs/abcjs/soundfont/`). Only GM program 0 (`acoustic_grand_piano`, 88 notes A0–C8, ~2.1MB) ships, so `%%MIDI program` is effectively ignored and every voice sounds as piano. The bank is an **opt-in installer task** (`abcsound`, default ON) fetched at install time like tikzjax, so "absent" is a normal state: `__abcSoundfontReady()` probes `C8.mp3` once per session (the note fetched *last*, hence a completeness marker) and asynchronously demotes the bar to disabled + `t('abc.noSoundfont')` — never delaying a render, never failing the document. `get_mime_type` gained `mp3`/`wav`/`m4a` (`rust-host.md`).
  - **Playback holds live DOM.** `TimingCallbacks`' `eventCallback` marks the sounding notes with `.abc-playing`, using the element references the visualObj captured at render time — so a staff restored from `__abcCache` has **no usable visualObj** (`staff.__abcVisual` is nulled on a cache hit) and `__abcPlay` re-renders that one block before starting. `renderMarkdown()` / `renderMarp()` call `__abcStop()` immediately before rebuilding `#preview`, so a keystroke, theme change or language switch stops the music rather than leaving an orphaned synth. One tune sounds at a time and one `AudioContext` serves the session — created and **resumed inside the click**, since it starts suspended under the autoplay policy and only a user gesture may resume it. ⚠ That resume is raced against `__ABC_RESUME_TIMEOUT_MS`: `resume()` settles only once the policy is satisfied, so where the click did not count as a gesture the promise stays pending forever and the button would sit on 「音源を読み込み中」 with no way out; on timeout the suspended-state check reports `abc.audioBlocked` instead. Reproduce it with a programmatic `.click()` — a real click always carries the gesture, which is why only a scripted driver sees this path.
  - **The bar is hover-revealed**, following `.copy-button`: `opacity: 0` until `.abc-notation:hover` / `:focus-within`, plus an `.abc-bar-active` class that `__abcPlay` sets and `__abcStop` clears so a sounding tune keeps its transport and progress on screen after the pointer leaves (an error message pins it open for the same reason). Unlike `.copy-button` it is **in the flow, not absolutely positioned**, so it is hidden with `opacity` and keeps its space — collapsing it would make every staff jump as the pointer crossed. That reserved row is why it still needs its own entry in all three suppression surfaces even though it is already transparent there: the `@media print` block, the `body.capturing` list (`--export-png`), and `buildExportArtifact()`'s strip — which also clears any `.abc-playing` left mid-tune. `shoot-docs.py` hovers the figure (`_GALLERY_HOVER`) or the docs gallery would advertise an empty gap. Playback is deliberately **not** re-implemented inside an HTML artifact: the artifact cannot reach the sound bank. See `export.md`.

- **Markwhen timelines** — fenced ` ```markwhen ` blocks contain [markwhen](https://markwhen.com/) text (a markdown-like timeline DSL) and are rendered as a **horizontal cascading timeline** (custom inline-SVG renderer; no iframe / Vue view). The bundled [`@markwhen/parser`](https://www.npmjs.com/package/@markwhen/parser) (esbuild IIFE at `assets/libs/markwhen/markwhen.iife.js`, exposing `window.Markwhen`, lazy-loaded by `ensureMarkwhen()` the first time a `markwhen` block appears) does all the date work — `parse(src)` returns a single timeline whose `events` tree resolves every event's `dateRangeIso.fromDateTimeIso` / `.toDateTimeIso` to absolute ISO strings, so the renderer needs **no runtime date library** (`Date.parse` only). Post-`marked.parse()` the block is replaced with `<div class="markwhen-timeline" data-markwhen-source="…">`; `renderMarkwhenCached(el)` in `assets/index.html` then: walks the `events` tree (`Markwhen.isEvent()` distinguishes an `Event` from an `EventGroup`), flattening it into rows — each `EventGroup` with a non-empty `title` emits an indented section label and bumps the depth; each `Event` emits a row using `firstLine.restTrimmed` as its label; gets the overall span from `Markwhen.ranges(root, [])` (`{fromDateTime,toDateTime}`, falling back to scanning events); picks axis tick granularity (years > ~3y span, else months, else day-ish); and emits one responsive `<svg>` (`viewBox` + `width:100%`/`height:auto`) with gridlines + a time axis, one row per item, **range events as bars / single-date events as dots**, positioned by date. Tag color comes from the markwhen header (`#tag: color` lines — the parser escapes the leading `#` to `)`, so the lookup is `header[")"+tag]`, validated with `CSS.supports('color', …)`), else a stable hashed palette color; light/dark palettes are chosen at render time. Memoized via `__markwhenCache` keyed by `__diagKey(src)` (theme-salted, since concrete colors are baked into the SVG — see *Diagram render memoization* (`preview-core.md`)). Errors render as a `.markwhen-error` red-bordered block in place; other blocks are unaffected. Output is pure inline SVG so **HTML export carries through with no special snapshot handling**, and it works in **Marp** via the same `code[class*="language-"]` substitution loop (`.markwhen-timeline` is included in the `.marp-fig` figure detection so a timeline on a non-split slide is horizontally centered). Built by `tools/build-markwhen/` (see *Architecture → Tools* (`build-and-deps.md`)). Sample: `samples/markwhen.md`.

  - **Calendar view (`display: calendar`) + online holidays** — adding `display: calendar` (or the boolean alias `calendar: true`) to the markwhen **header** switches the same data to a **month-grid calendar** SVG instead of the timeline. **`view` is NOT usable** — it's a reserved markwhen header key that the parser mangles (`view: calendar` → an empty array), whereas non-reserved keys like `display` / `calendar` / `country` are preserved verbatim, so the trigger reads `mw.header.display === 'calendar'` / `mw.header.calendar === true`; anything else keeps the timeline. `renderMarkwhenCached` is therefore **`async`**, and the two render loops (normal + Marp) now `await Promise.all(...)` over the blocks (mirroring the plotly loop) so the finished DOM — with holidays — is in place before `__emitRenderDone`, i.e. before HTML export / `--export-png` capture snapshots it. The shared parse/flatten/timeline logic was extracted into `__mwFlatten()` / `__mwBuildTimeline()`; the calendar is built by **`__mwBuildCalendar(mw, events, holidays)`**, which renders **consecutive month grids from the first event's month to the last** (single-day events → chips, multi-day ranges → week-spanning bars, packed into per-week lanes FullCalendar-style with a `+N` overflow indicator, a tag→color legend, JP weekday headers with Sun/Sat coloring). Very wide spans fall back to the timeline with a `.markwhen-note`: the `__MW_CAL_MAX_MONTHS = 36` cap guards against a decade-spanning history producing hundreds of grids. **Holidays are online-only** (`navigator.onLine`-gated) so the offline-by-design guarantee holds: `__mwFetchHolidays(country, years)` fetches from **nager.at** (`https://date.nager.at/api/v3/PublicHolidays/{year}/{country}`, free/keyless/CORS-`*`; `date` is already `YYYY-MM-DD`, `localName` is the local-language name — Japanese for JP) with an `AbortController` timeout (`__MW_HOLIDAY_TIMEOUT_MS = 4000`), caches per `(country, year)` in `__mwHolidayCache`, and **swallows all failures** (offline/network/timeout/bad-JSON) → no holidays, no error, normal render. Default country is **JP**, overridable via a `country:` header key. Holiday cells get a distinct accent fill + the holiday name; the day number recolors. Calendar renders are memoized in a **separate `__markwhenCalCache`** keyed by `` `${__diagKey(src)}|cal|${country}|${online?'on':'off'}` `` so an offline→online transition (holidays appear) correctly re-renders. Colors are baked into the SVG (theme-salted, like the timeline), so export / Marp carry the calendar — and any online-fetched holidays — through unchanged. Sample: the `display: calendar` block in `samples/markwhen.md`.

- **tikz-cd commutative diagrams (` ```tikzcd `) + general TikZ (` ```tikz `)** — fenced blocks are rendered to **inline SVG by a WASM TeX engine**, [@rod2ik/tikzjax](https://www.npmjs.com/package/@rod2ik/tikzjax) (`assets/libs/tikzjax/dist/`, ~7.7MB: `tikzjax.js` orchestrator + `run-tex.js` engine + `tex.wasm.gz` + `core.dump.gz` + `fonts/*.woff2` + on-demand `tex_files/*.gz`). This is the project's **first WebAssembly** dependency and **first copyleft (GPL/LPPL)** dependency; it's **fully offline** and **lazy-loaded** by `ensureTikz()` only when a `tikz`/`tikzcd` block appears (docs without one pay nothing). `ensureTikz()` sets `window.TikzJaxOptions.assetBaseUrl` to an **absolute** URL (`new URL('libs/tikzjax/dist', document.baseURI)`) — the TeX engine runs in a blob **Web Worker** whose base URL is opaque, so a relative base can't resolve the on-demand `tex_files/*.gz` fetches (they'd 404 and break package loads like tikz-cd) — and injects a `<link>` to `fonts.css` (glyphs are PUA-mapped `<text>` in the Computer-Modern web fonts, not embedded paths). Post-`marked.parse()` each block becomes `<div class="tikzcd-diagram|tikz-diagram" data-tikz-kind="cd|raw" data-tikz-source="…">`; **`renderTikzCached(el)`** injects a `<script type="text/tikz">` (auto-wrapping a `tikzcd` body in `\begin{tikzcd}…\end{tikzcd}` with `data-tex-packages='{"tikz-cd":"","amssymb":""}"`; the body is **whitespace-trimmed** because a blank line inside a tikzcd matrix becomes a `\par` → the cryptic "Missing $ inserted") which tikzjax's `document.body` `MutationObserver` auto-compiles in the worker; `__tikzAwait(el)` resolves when the wrapper drops its `tikzjax-loading` class (success **or** a broken-image failure — no 30s wait) or on a 30s timeout, then the finished `el.innerHTML` is memoized. **Diagrams render small, so they're enlarged by default** — `__applyTikzScale()` multiplies the finished SVG's intrinsic `width`/`height` (its `viewBox` drives clean scaling; `max-width:100%` still caps an oversize result) by `__TIKZ_SCALE = 1.6`, overridable per block with a leading `scale: <n>` directive line (stripped before the TeX body, mirroring mermaid's `scale:`; the full source incl. that line keys the cache). **NOTE** some diagrams (curved/diagonal arrows) contain a dvisvgm-emitted *nested* `<svg>` inside the outer one — `__applyTikzScale` scales the **outer** wrapper svg only, so the whole figure scales together. Cache **`__tikzCache`** is un-salted (keyed by `kind+source`, like abc) because the SVG uses `stroke/fill=currentColor` → **dark mode is a CSS `color` change** (`body.dark-mode .tikzcd-diagram .tikzjax-wrapper { color:#d0d0d0 !important }` overrides tikzjax's inline black). A failed compile (tikzjax's `.tikzjax-broken-wrapper`/`.tikzjax-broken-image`) is replaced with a styled `.tikz-error` block. **Rendering is fire-and-forget (NOT awaited before `__emitRenderDone`)** — a TeX compile takes seconds and a bad diagram waits out the 30s timeout, so awaiting it would freeze the "読み込み中" splash (hidden only after `renderMarkdown` resolves); each block shows a "コンパイル中…" placeholder and fills in async. Wired into **both** pipelines (Marp uses the same `renderTikzCached`; `.tikzcd-diagram`/`.tikz-diagram` are in the `.marp-fig` figure-centering set). **HTML export**: the inline SVG carries through the cloned DOM, but glyphs need the CM fonts — so `buildExportArtifact()` collects the `font-family` values used across tikz SVGs and inlines just those `libs/tikzjax/dist/fonts/<name>.woff2` as base64 `@font-face` (else PUA glyphs render as blank tofu). **`--export-png` does NOT capture tikz** — the headless hidden window can't run the wasm Web Worker (documented limitation; awaiting would hang, which is another reason rendering is fire-and-forget).
  - **Japanese / CJK labels — TeX reserves the box, the browser draws the glyph.** The engine *cannot* typeset CJK: `inputenc`'s utf8 layer raises `UTFviii@undefined@err` on any undeclared codepoint (so no `input.dvi` at all, and the whole block fails), and even declared there is no glyph to set it with — `dist/fonts` is Computer Modern + AMS only and `tex_files` carries no CJK TFM. So `__tikzJpPreamble(body)` scans the body, and for each CJK codepoint that actually occurs emits a `\DeclareUnicodeCharacter` mapping it onto **`\mdpJp`**, an `\hbox` of the right width whose only content is a `dvisvgm:raw` special. `run-tex.js`'s `putSVG()` writes that string into the SVG verbatim with `{?x}` / `{?y}` replaced by the current DVI position in points — the same coordinate space the engine's own glyphs use. The generated preamble rides a new **`data-add-to-preamble`** attribute (tikzjax reads it off the script element's `dataset`, exactly like the existing `data-tex-packages`), and is emitted **only when a CJK codepoint was found**, so a Japanese-free block is byte-identical to before — `gate.sh` confirms it. Five things are load-bearing:
    - ⚠ **The character never reaches TeX.** The special carries only the hex codepoint in `data-mdp-jp` and the `<text>` is emitted EMPTY; **`__tikzFillJpText()`** fills in `textContent` after the compile. That is what keeps the TeX source pure ASCII, so no catcode-active byte, `&` or `#` can ever land inside `\special` — and it is also why `__b64FromText`'s "a figure's labels are routinely Japanese" comment is now literally true of the SVG itself. It runs **before `__diagCacheSet`**, so the memoized innerHTML already carries the glyphs and every cache hit, HTML export and figure save gets them for free.
    - ⚠ **The size must follow the MATH STYLE, not the font.** tikz-cd sets arrow labels in `\scriptstyle` (its `every label` style appends `\scriptstyle` to `\everymath`), and a subscript does the same — but `\font`, and therefore `1em`, is **not** switched by math style. A flat `1em` puts a 10pt Japanese label beside 7pt Latin, ~43% oversized. `\mdpJp` therefore picks the size with `\mathchoice` over `\fontdimen6` of `\textfont0` / `\scriptfont0` / `\scriptscriptfont0` (family 0 is the roman math family, whose quad is its design size). TeX ships only the selected `\mathchoice` branch, so this still emits exactly **one** `\special` per character — measured, not assumed.
    - ⚠ **The `font-size` must end up unitless.** The engine's viewBox numbers one user unit as one TeX **point**, but SVG resolves a `pt` font-size through CSS (1pt = 4/3 px = 4/3 user units). `\the` prints `10.00002pt`, which would draw the glyph 1.333× wider than the box TeX reserved — measured 13.333 vs 10.004 user units for 日 at 10pt. `__tikzFillJpText()` strips the suffix.
    - ⚠ **The font stack goes in `style=`, never `font-family=`.** `buildExportArtifact()` walks `[font-family]` via `__tikzFontFamilies()` to decide which Computer-Modern woff2 to inline, and a family that is not one of the engine's own would send it after a `fonts/<name>.woff2` that cannot exist. It also carries **no apostrophes** (a multi-word CSS font name is valid unquoted), because the whole preamble travels in a single-quoted HTML attribute whose payload needs double quotes for the SVG attributes. The stack is `SPAN_FONT_STACK.serif` with the quotes stripped — one source, not a sixth copy.
    - `\leavevmode` is guarded as `\ifvmode\leavevmode\fi`: LaTeX defines it as `\unhbox\voidb@x`, which is an **error in math mode**, and `\ifvmode` is false there while being true exactly where an unboxed `\hbox` would otherwise start its own line (the first thing in a `text width=` node).
    - **Adjacent specials cannot collide**, although `run-tex.js`'s `function N` merges strictly-consecutive raw-SVG nodes into one (sharing a single `{?x}` substitution). TeX's `special_out` calls `synch_h` before writing each `xxx`, so a non-zero-width box between two specials forces a horizontal movement node into the stream and breaks the run. ⚠ The corollary: **never emit a zero-width box** — halfwidth forms get 0.5em, everything else 1em, and nothing gets 0.
    - **Transforms need no handling.** The `<text>` lands at the same stream position a real glyph would, so it ends up in the *same parent* with the *identical* ancestor `<g>` transform chain — verified against the cmr10 glyphs of the same label, including a `rotate=45` node. (`putSVG` itself ignores `this.matrix`, but pgf does its transforms with nested `<g>`, so that never bites.)
    - **Limits:** the glyphs come from the reader's **system** Japanese font, so an HTML export opened where none is installed falls back (embedding a CJK face would cost megabytes — deliberately not done; the CM inlining is unaffected). Greek and Cyrillic are deliberately **out** of the set and still fail — `err.tikzJaCompile` says so, and they almost always want `\alpha`-style commands anyway. Latin-1 / Latin Extended-A is also out **on purpose**: `inputenc` already sets é / ü with real CM glyphs, and rerouting those would be a regression. `src/main.rs` `get_mime_type` gained `Some("wasm") => "application/wasm"` (the `.gz` assets stay `application/octet-stream` and are decompressed in JS). Fetched (as an extracted npm tarball) by `tools/fetch-libs.ps1`. **NOT shipped in the installer** — it is GPL-3.0-or-later with LPPL TeX packages and compiled WASM binaries, and conveying a compiled GPL binary would oblige us to offer its Corresponding Source; an opt-in installer task downloads it from the npm registry at install time instead, so the product never conveys it (see *Architecture → Build / installer / icon* (`build-and-deps.md`)). Consequently **the engine may legitimately be absent at runtime**, and that is a first-class state rather than a fault: `src/main.rs` probes `assets/libs/tikzjax/dist/tikzjax.js` next to the other init-script globals and injects **`window.__tikzAvailable`**, which `assets/index.html` reads through **`__tikzUnavailable()`**. **Undefined means available** — `tools/preview-harness/serve.py` injects the other host globals but not this one, so the flag may only ever *suppress*, never enable; inverting that would silently kill tikz for every harness run. When it is false, `ensureTikz()` rejects immediately (no `<script>` is injected that could only 404) and both pipelines swap in **`__tikzUnavailableHtml()`**, which distinguishes *never installed* (actionable: re-run the installer and tick the box) from *installed but failed to load* (a real fault). The protocol handler's 404 `dbg_log!` gate also covers `/libs/` so an absent engine is diagnosable from `md-previewer.log`. Sample: `samples/tikzcd.md` and the 可換図式 slide in `samples/marp.md`.

- **Kataskeve geometry diagrams (` ```kataskeve ` 2D + ` ```kataskeve3d ` 3D)** — two independent MIT, zero-dependency engines bundled from their GitHub repos ([kataskeve](https://github.com/yvvakimoto/kataskeve) 0.1.1 / [kataskeve3d](https://github.com/yvvakimoto/kataskeve3d) 0.1.0), lazy-loaded by `ensureKataskeve()` / `ensureKataskeve3d()` so docs without a block pay nothing. **Both loaders must call `initialize({ startOnLoad: false, injectStyles: false })`**: each bundle schedules its own mermaid-style auto-init with `setTimeout(boot, 0)`, which would scan `.kataskeve, pre code.language-kataskeve` and stamp `data-…-processed` on our still-empty host divs — `loadLib` resolves inside the script's `onload` *task*, so the `await` continuation is a microtask of that task and provably beats the timeout. `injectStyles:false` because the app owns the CSS: `buildExportArtifact()` inlines only the document's **first** `<style>`, so a library-injected (or `<link>`ed) ruleset would silently vanish from every HTML export — which is also why neither package's `.css` is fetched at all (both are container/error chrome only). **The two engines are opposites in almost every respect, and those differences are the design:** (1) *output* — 2D `render(src)` is a **pure string→string** call returning a complete inline `<svg>`, so it caches, exports and Marp-embeds like mermaid; 3D `renderElement(src, host)` **rasterizes into a `<canvas>` and wipes the host**, and there is no string-returning API. (2) *caching* — see *Diagram render memoization* (`preview-core.md`); the 3D path is the one place `__diagCacheHit` is forbidden. (3) *errors* — **neither engine throws**; both produce an English `<div class="kataskeve[3d]-error">Kataskeve[3D] error: …</div>`, so the failure signal is that class, not an exception, and `__ksLocalizeError()` swaps the engine's prefix for `t('err.prefix', {engine})` while keeping the upstream message body. Errors are **not cached**, so a half-typed diagram recovers on the next keystroke and a `setUiLang()` re-render cannot serve a stale-language prefix. (4) *theme* — 2D paints in `currentColor` except the optional grid/axis colours, which the engine picks from **`body.dark-mode`** (this app's own convention, so it works for free); 3D takes its ink from `getComputedStyle(host).color`, which means **the host must be attached to the document** — on a detached node Chromium returns an empty colour and the ink silently falls back to a dark `#1a1a1a`, invisible in dark mode. `display:none` is fine (a computed colour still resolves), which is why a Marp deck's slide 2 renders correctly. (5) *export* — 2D needs nothing; 3D gets a rasterization pass (see *Export* (`export.md`)). **No `viewBox` surgery is needed for the 2D SVG** (unlike `renderAbcCached`): kataskeve already emits one, so the element has an intrinsic ratio and `max-width:100%` *scales* rather than clips inside a narrow Marp split column — verified in the split-column slide of `samples/marp.md`. **`penrose_triangle` walks ancestors for the first opaque `background-color` to use as "paper" and defaults to WHITE**; it finds `#preview-container` (white / `#0d1117`) and in Marp the slide `<section>`, so **no background rule was added** — measured, the dark render paints zero opaque-white pixels. **Both renders are `await`ed** in both pipelines (unlike tikz's fire-and-forget): they are synchronous CPU work with no worker, and `--export-png` only captures what landed before `__emitRenderDone`. The await is written `xReady || ensureX()` inside a `try/catch` falling back to `__ksFailAll()`, because a **tilde fence** (`~~~kataskeve`) becomes `class="language-kataskeve"` from marked — hence a host div — but escapes the ```-anchored `needsX` regex, so the bare `if (xReady) await xReady` idiom would let a `TypeError` abort the entire render past pagination, the TOC and `__emitRenderDone` (hanging `--export-png` and leaving the splash up). That hazard pre-exists for abc / plotly / markwhen and is deliberately left alone there. **Fence disambiguation is safe at every site but for a different reason at each**, and each is commented: the normal pipeline's `html.replace` patterns are disjoint because the closing `"` is inside them (`language-kataskeve"` cannot match `language-kataskeve3d"` — the same guarantee the tikz/tikzcd pair already relies on); Marp's `lang === 'kataskeve'` is exact equality over a token captured by `language-([A-Za-z0-9_+-]+)`, which includes digits; `needsKataskeve` is `/```kataskeve(?!3d)\b/` where the `\b` **alone** already suffices (`e`→`3` is a word→word transition, so no boundary exists there) — the lookahead is spelled out only because this is the exact opposite of `/```tikz(cd)?\b/`, which matches both fences on purpose; and `[data-kataskeve]` does not match `data-kataskeve3d` because attribute-presence selectors are exact-name (do **not** "simplify" that to `*=` or `^=`). **No Rust change was needed**: `get_mime_type` already serves `.wasm`, assets are read off disk, and the installer ships `assets\*` recursively (only `libs\tikzjax\*` is excluded) — unlike tikzjax these are MIT, so they are bundled normally and need no `__tikzAvailable`-style availability gate. Samples: `samples/kataskeve.md`, `samples/kataskeve3d.md`, and the two Kataskeve slides in `samples/marp.md`.

- **Feynman diagrams (` ```feynman `) via feynmark** — fenced ` ```feynman ` blocks contain a declarative, Mermaid-style DSL ([feynmark](https://github.com/yvvakimoto/feynmark), MIT — the same author as this project; bundled as a single IIFE at `assets/libs/feynmark/feynmark.min.js`, lazy-loaded by `ensureFeynmark()` the first time a `feynman` block appears) for particle-physics Feynman diagrams: one or more `diagram { ... }` / `equation { ... }` statements per fence, with declarative propagator styles (`fermion`, `photon`, `gluon`, `scalar`, `ghost`, `boson`, `double`, `majorana`, `graviton`, …), edge/vertex attributes (`label`, `momentum`, `bend`, `color`, `dot`/`blob`/`cross`, `at (x,y)`), hadron `brace` brackets, and `equation` blocks that embed `@diagramName` as inline terms in a KaTeX-rendered formula. Post-`marked.parse()` each block becomes `<div class="feynman-block" data-feynman-source="…">`; **`renderFeynmarkCached(root)`** loops its `.feynman-block` elements synchronously (like `renderAbcCached`, not `Promise.all` — feynmark's `render`/`renderInto` are synchronous, no async compile step) and calls `window.feynmark.renderInto(el, src)` directly rather than feynmark's own `run()`, because `run()`'s built-in error-box handling isn't reachable from a direct `renderInto` call — `renderInto()` throws synchronously on a parse/layout/unknown-`@ref` error, so md_previewer wraps it itself and builds its own error box (escaping `FeynmarkError.excerpt()`, which returns plain text). **Class names deliberately use `feynman` (no "k")** — `.feynman-block` (the outer per-fence container) / `.feynman-error` (md_previewer's own error box) — to avoid colliding with feynmark's own internal wrapper classes (`.feynmark-diagram` per un-referenced diagram, `.feynmark-equation` per equation, root `<svg class="feynmark">`, its own unused `.feynmark-error`). feynmark renders with `stroke/fill: currentColor` (verified in its `render/theme.ts`), so — like `abc`/`tikz`, unlike `mermaid`/`markwhen` — **dark mode needs no re-render and the memoization cache (`__feynmarkCache`) needs no theme salt**, keyed by the raw source directly (see *Diagram render memoization* (`preview-core.md`)). feynmark optionally uses **KaTeX** (already bundled, lazy-loaded the same way) for math labels and `equation`/`@name` embedding — it never imports KaTeX itself, resolving `window.katex` at render time and falling back to plain text if absent — so md_previewer's `needsFeynman` gate awaits `Promise.all([ensureFeynmark(), ensureKatex()])` regardless of whether the document's own `$...$` math is present. `@name` references only resolve against diagrams defined earlier in the *same* `renderInto()` call, so the entire fence is always rendered as one source string into one container div (never split per-diagram), mirroring the markwhen/abc/tikz "one fence, one div" convention. Works in both pipelines (`.feynman-block` is in the Marp `.marp-fig` figure-centering set and the `::: vcenter` reset); output is pure inline SVG (+ `<foreignObject>` KaTeX for equations) so **HTML export carries through with no special snapshot handling**, same as markwhen/abc. - **3D mesh files (` ```model3d `) via three.js** — a `model3d` fence holds a small YAML spec (parsed with the same `ensureJsYaml()` plotly uses) naming an **external mesh file**, which is loaded through the existing `/userfile/` route and rendered **interactively** (drag to orbit, wheel to zoom) by [three.js](https://threejs.org/) 0.185.0 (MIT), bundled by `tools/build-three/` as `assets/libs/three/three.iife.js` (~665KB min, lazy-loaded by `ensureModel3d()`). Formats: `stl` (binary/ASCII), `obj` (+ optional `mtl:`), `ply`, `gltf`, `glb`, `3mf`. A YAML body that resolves to a bare **string** is treated as `{ file: <that string> }`, so the shortest form is just the path on its own line. This is the repo's **first WebGL** dependency and its **first engine that is I/O-bound on the awaited path** (every other awaited engine — kataskeve, kataskeve3d, feynmark, abc — is pure CPU), which is why it carries an `AbortController` timeout and a byte cap.
  - **`window.Model3D` is our own facade, not three's namespace.** `tools/build-three/entry.js` exports only the facade (`available` / `mount` / `unmountAll` / `flushNow` / `invalidate` / `hashString` / `_debug`), and that is load-bearing for size: with `format:'iife'` the entry's exports *are* the public surface, so `export * from 'three'` — which is exactly what the sibling `tools/build-markwhen/entry.js` does — would defeat tree-shaking entirely and cost ~890KB instead of ~665KB. `three/webgpu`, `three/tsl` and any `renderers/webgpu/*` / `examples/jsm/tsl/*` module must never be imported: they carry top-level await, which cannot be expressed in an IIFE.
  - ⚠ **ONE renderer for the whole page, on a detached canvas, living outside `#preview`.** `#preview` is rebuilt by `innerHTML` on every render including every ~150ms live-edit keystroke, so a per-block `WebGLRenderer` would leak a context per keystroke and silently blow past Chromium's ~16-context page cap — and release builds have no devtools, so the symptom is *older figures going blank with no message*. The renderer is sized **grow-only** (`setSize(maxW, maxH, /*updateStyle*/ false)`, capped at 2048/axis) and each block is drawn into a scissored viewport; `setPixelRatio()` is never called. `webglcontextlost` is `preventDefault()`ed and `webglcontextrestored` drops the model cache, since every GPU-resident buffer dies with the context.
  - ⚠ **The visible canvas is 2D, not WebGL.** Each block owns a plain 2D `<canvas>`; the GL result is blitted in with `drawImage` **in the same task** as the `render()`. That is what makes the captured surface a 2D canvas whose bitmap `toDataURL()` reads back — the exact path kataskeve3d already proved through HTML export, PDF and `--export-png` — and it means block count and keystroke count never multiply WebGL contexts. `preserveDrawingBuffer: true` is set as belt-and-braces: same-task blit is already safe (the implicit clear happens at a composite checkpoint, and this canvas is never composited), but the day somebody splits render and blit across tasks the failure is a black figure with no error. **Measured in the hidden `--export-png` window: `webgl2` OK on a real GPU (ANGLE/D3D11), blit pixels correct, `toDataURL` fine** — so unlike tikz there is no hidden-window capability hole.
  - ⚠ **The GL viewport origin is bottom-left; `drawImage`'s source rect is top-left.** Rendering into `setViewport(0, rendererH - h, w, h)` puts the region at `(0, 0, w, h)` in canvas space, making the blit source rect trivial. Verified empirically. Pick one convention and never mix them.
  - **Three caches, all outside `#preview`, and none of them is `__diagCacheHit`** — see *Diagram render memoization* (`preview-core.md`). A **model LRU** keyed on `url + '|' + Last-Modified` (cap 8) so only the first keystroke pays disk + parse, and so a re-export from a CAD tool actually invalidates; a **rendered-bitmap LRU** keyed on `hash(src)|ordinal|cameraHash|themeSalt` (cap 12 — kataskeve3d's 64 would be ~320MB at 5MB an entry) so a keystroke in prose costs a handful of `drawImage` calls and zero GL work; and a **camera-state map** keyed on `hash(src)|ordinal` so orbiting survives a keystroke and two byte-identical fences do not share one camera. Materials come from a small **fixed palette**, because a material per render leaks a `WebGLPrograms` cache entry (a program is only released when its material is disposed) *and* pays a 10–50ms shader compile each time; `keycheck.py` asserts `renderer.info.programs.length` stays flat across rebuilds.
  - ⚠ **Size comes from the fence spec (`width:` / `height:`, default 680×460) and is NEVER measured from layout.** `clientWidth` is 0 for a `display:none` deck slide, reports the *untransformed* value in list mode, and is different again after `__marpPrepareForPdf()` / `__prepareCapture()` have rebuilt the layout — so a layout-derived figure would have a pixel size that depends on which view mode it happened to render in, making `domdump.py` / `shoot.py` digests view-mode dependent. Fixing the size instead eliminates the Marp `display:none` problem, the need for a `ResizeObserver` (and its leak), and any measurement in the export pass. The cost — a figure that cannot fill a wide window — is the same trade kataskeve3d made deliberately.
  - **The backing store is 2× the logical size (`__MODEL3D_SS`), which is the one place model3d deviates from kataskeve3d.** `src/png_win.rs` passes `clip.scale` = `--png-scale` (default 2) to `Page.captureScreenshot`, so a bitmap at CSS size is *resampled* 2× by the compositor — which is why kataskeve3d's `--export-png` output is soft today. A 2× store rasterizes 1:1. The factor is a **literal 2, deliberately not `devicePixelRatio`**: real DPR would make exported PNG bytes machine-dependent and break the digests on any display not at 100%. The consequence is that the HTML export must pin the `<img>` width — see *Export* (`export.md`).
  - **Camera auto-fit fits the bounding BOX, not the bounding sphere.** A sphere fit is one line and viewing-angle independent, but for the flat or elongated parts most CAD exports contain it leaves roughly half the box empty. `buildScene()` builds the same basis `lookAt()` will (`z = dir`, `x = up × z`, `y = z × x`), projects the 8 bbox corners onto it, and takes the distance the worst corner needs. `spec.camera.distance` overrides it as a multiple of the bounding radius.
  - **Path resolution must produce an ABSOLUTE `/userfile/` URL**, even when the path does not escape the document directory (the case where `toUserfileUrl()` would keep it relative). This is load-bearing for glTF, not cosmetic: three resolves a `.gltf`'s sibling `.bin` / textures with `LoaderUtils.extractUrlBase()`, which is plain string manipulation, and from a shallow base a uri of `../tex/x.png` becomes `/userfile/../tex/x.png` — which the URL parser then collapses *past* the `/userfile/` prefix, losing the route (the same trap `relPathEscapesBase()` guards for images). An absolute Windows path is always deep enough that `..` cannot reach the prefix. The URL must also stay **origin-relative**: `resolveURL()`'s host-relative branch fires on an `https` base and would truncate it to the bare origin. A `LoadingManager.setURLModifier()` routes every sub-resource through `encodePathForUserfile()`, without which a Japanese folder or texture name 404s (`%E6` → `%25E6` is unrecoverable in Rust — CLAUDE.md #16).
  - **Two loader families, and the split is deliberate.** Self-contained formats (`stl` / `ply` / `3mf` / `glb`) are fetched by the engine itself so the byte cap and the abort timeout actually apply, then handed to the synchronous `.parse()` (`glb` uses `parseAsync`, since `GLTFLoader.parse` is callback-based). Formats that resolve sibling files (`gltf`, `obj` + `.mtl`) go through `loader.load()` so three does that resolution. `THREE.Cache` is off by default and **must stay off**, or a changed file on disk would never be re-read.
  - **`color:` overrides three's placeholder material but never the file's authored one.** STL/PLY carry no materials, and an `.obj` with no `.mtl` gets a grey default — overriding that is what the user means; overriding a textured glTF's materials would wreck it. The engine tracks this as `hasFileMaterials`.
  - **Errors are never cached**, so a half-typed spec recovers on the next keystroke and a `setUiLang()` re-render cannot serve a stale-language message. Six i18n keys of its own (`err.model3dNoWebgl` / `NoFile` / `Format` / `TooLarge` / `Timeout` / `Missing` / `Draco`) on top of the shared `err.prefix`; a 404 names the file, following plotly's message shape.
  - **WebGL absence is a first-class state**, like `__tikzUnavailable()`. A memoized `WebGL.isWebGL2Available()` (`three/addons/capabilities/WebGL.js`, default export — `isWebGLAvailable()` was removed in r163) gates the render; `getWebGL2ErrorMessage()` is deliberately **not** used, being hard-coded English with an inline white background.
  - ⚠ **`unmountAll()` must run before `#preview` is rebuilt, from BOTH pipelines** (`__model3dUnmount()` sits next to `__abcStop()` at each rebuild site; one site only is a half-fix that passes every non-Marp test). The leak it prevents is not the listeners on the canvas — those die with the node — but the `pointermove`/`pointerup`/`pointercancel` handlers OrbitControls attaches to `domElement.ownerDocument` **during a drag**: a keystroke mid-drag leaves them holding the dead canvas, camera and scene. It also zeroes the outgoing canvases (≈5MB each; six blocks at 150ms is ~200MB/s of garbage, and leaving that to GC is felt as a stutter). `enableDamping` is off because damping mandates a standing rAF loop, which is what the on-demand design exists to avoid.
  - **Rendering is on demand with a synchronous flush.** No standing rAF loop; the scheduler races rAF against a `setTimeout` (the `__nextPaint()` shape) and `flushNow()` renders everything synchronously, so the hidden `--export-png` window gets real pixels. Both pipelines **await** the render before `__emitRenderDone`. No `__nextPaint()` beat is needed anywhere, because nothing is measured.
  - **Fence disambiguation needs no lookahead**: `model3d` shares no prefix with any other fence, so the plain `\b` in `needsModel3d` suffices — the opposite of the `kataskeve`/`kataskeve3d` pair, and the comment says so to stop someone adding one. `assets/libs/three/` is MIT and ~665KB, so unlike tikzjax the installer ships it normally through the existing `assets\*` recurse; no availability gate, no opt-in task. ⚠ **fflate 0.8.2 (MIT) is bundled invisibly**: three vendors it at `examples/jsm/libs/fflate.module.js` and `3MFLoader` imports it to unzip `.3mf`, so it is not an npm dependency and `collect-licenses.ps1` needs a hand-written `$direct` entry (`legalComments:'none'` strips the in-bundle banner). Rust needed only MIME arms plus a new `Last-Modified` header on `/userfile/`. Sample: `samples/model3d.md` and the 3D モデル表示 slide in `samples/marp.md`. **Extension point**: STEP/IGES would slot in as a pre-pass converting to a mesh before `mount()` (occt-import-js, ~8MB WASM, LGPL) — which is the tikzjax "large + copyleft" class and would need an opt-in installer task and a `__xAvailable`-style gate.

- **KaTeX math** — `$...$` and `$$...$$` are extracted via `extractMathInto` placeholder pass *before* `marked.parse` and rendered as pre-rendered spans afterward. Same placeholder pass runs on footnote bodies so footnote math, tooltips, and exported artifacts all share the same KaTeX output. `renderMathExpressions()` renders with **`output: 'htmlAndMathml'`** (not html-only) so each expression carries a hidden `<span class="katex-mathml"><math>…</math></span>` whose `<semantics>` includes an `<annotation encoding="application/x-tex">` with the original LaTeX. This powers **`setupMathContextMenu()`** in `assets/index.html`: a single delegated `contextmenu` listener on the stable `#preview` element (wired once, guarded by `__mathMenuWired`, so it survives the per-render `innerHTML` rebuild) shows a right-click **"Copy MathML / Copy LaTeX"** menu on any `.katex` element — MathML via `XMLSerializer` on the `<math>`, LaTeX from the `x-tex` annotation; a format absent from the DOM (e.g. an html-only `.katex`) is shown disabled. Right-clicking outside math falls through to WebView2's native menu (back/forward navigation). Works in both pipelines (Marp's marp-core KaTeX also emits MathML). Copy uses the shared **`copyTextViaTextarea()`** helper (the WebView2-safe `execCommand('copy')` fallback, also used by the code-block copy button). The MathML now also rides into exported HTML, harmlessly improving accessibility.

- **Syntax highlighting** — `highlight.js` colors code blocks; every block gets a copy button. The bundled `highlight.min.js` is the **common** build, so a language outside that set needs its own grammar module loaded after it. **Modelica** (` ```modelica `, aliases `mo` / `mos`) is provided that way by **`assets/libs/hljs-modelica.js`**, an **in-house, hand-written, git-tracked** definition (a `<script>` in `index.html` right after `highlight.min.js`; it self-registers via `hljs.registerLanguage`). It is hand-written rather than fetched by `tools/fetch-libs.ps1` for two reasons: highlight.js core ships **no** Modelica grammar (absent from the cdnjs / jsdelivr `languages/` set for 11.x), and the npm plugin `highlightjs-modelica` targets hljs v9/v10 — its `contains` ends in `hljs.METHOD_GUARD`, which **v11 removed**, so compiling it against the bundled 11.9.0 throws; it also treats `'...'` as a string when in Modelica single quotes delimit a **quoted identifier (Q-IDENT)**, and files `extends` / `partial` / `within` under built-ins. Two details of the grammar are load-bearing: the string mode is **not** `hljs.QUOTE_STRING_MODE` (that sets `illegal: \n`, but a Modelica documentation / annotation string may span lines), and the two multi-class `begin: [...]` rules that name a class carry negative lookaheads in their third group — `(?!(?:record|function)\b)` so `operator record Complex` names `Complex` rather than `record`, and `(?!(?:if|for|when|while)\b)` so `end when;` stays two keywords instead of tagging `when` as a class name. Being in-house it needs **no `THIRD_PARTY_LICENSES.txt` entry**, and it is **not** covered by the `.gitignore` enumeration of generated `assets/libs/` artifacts, so it is tracked by default. Registration is global, so it serves the normal pipeline and the Marp code-block re-highlight pass alike; HTML export needs nothing (the spans are already in the serialized DOM). Sample: the *Modelica* section in `samples/syntax.md`.

## Saving one rendered figure (right-click → SVG / PNG)

Right-clicking a rendered figure offers **「SVG として保存」/「PNG として保存」**, writing that
one figure to a file through a native Save dialog. It is the per-figure counterpart to the
whole-document `X` export, and it exists because there was no other way out: this WebView2
host wires up **no download plumbing at all** (nothing in `src/` handles a download and
`<a download>` is inert), so the bytes have to go to the host over IPC.

**Menu.** Built by `setupPreviewContextMenu()` in `assets/index.html`, which is the former
`setupMathContextMenu()` — the two are **deliberately one listener and one menu**. A
feynmark `equation{}` draws KaTeX inside a `<foreignObject>`, so a click there matches
`.katex` **and** `.feynman-block`; as two separate `__createContextMenu()` instances they
would both open, side by side. Merged, that click simply offers all four items. The table
edit-mode menu stays separate, for the reason `preview-tables.md` already gives (an editing
cell shows markdown *source*, so it can contain neither). Net: `keycheck.py`.

**Which blocks, and where the output lives.** `__FIGURE_KINDS` — the set `isFigureChild()`
centres in Marp, minus the tables:

| wrapper | kind | taken from |
|---|---|---|
| `.mermaid` | `mermaid` | `svg` |
| `.abc-notation` | `abc` | `.abc-staff svg` — ⚠ scoped, or the playback bar is a candidate |
| `.markwhen-timeline` | `markwhen` | `svg.mw-svg` (the calendar view is an SVG too, so it saves) |
| `.tikzcd-diagram` / `.tikz-diagram` | `tikzcd` / `tikz` | `.tikzjax-wrapper > svg` |
| `.kataskeve` | `kataskeve` | `svg` |
| `.feynman-block` | `feynman` | `svg` (one fence can hold several) |
| `.kataskeve3d` / `.model3d` | — | `canvas` → **PNG only** |
| `.plotly-block` | `plotly` | `Plotly.toImage()` |

⚠ `closest('.kataskeve')` does **not** match `.kataskeve3d`: class tokens are matched whole,
the same guarantee the fence regexes rely on. Do not "simplify" either selector to a prefix
match. Where a fence can hold several diagrams, or where dvisvgm nests an `<svg>` inside a
tikz figure, the **outermost `<svg>` between the click and the wrapper** wins.

**The menu appears only when an `<svg>` or a `<canvas>` is actually present**, and that one
rule is load-bearing: it is what keeps the renderers' error boxes, a still-compiling tikz
placeholder, and `csv` / GFM tables out of the menu without a single special case. With no
items the event is left alone, so the WebView2 native menu (back / forward) still shows —
the same contract `setupFileTreeContextMenu()` keeps.

**`__serializeFigureSvg()` is not `outerHTML`.** Four things have to be repaired, because
each is something the live page was supplying from outside the element:

- **Size.** `__abcMakeResponsive()` leaves `width="100%"` and no `height` at all, and
  `applyMermaidScale()` writes `style="max-width:Npx"`. Neither means anything in a file, so
  the real box is recovered from the `viewBox` and pinned as `width`/`height`.
  ⚠ The `viewBox` is consulted **before** any measured box: `getBoundingClientRect()` is 0×0
  for a figure on a `display:none` deck slide — the same fact that makes model3d take its
  size from the fence spec.
- **Ink.** abc / tikz / kataskeve / feynman all paint in `currentColor` (which is exactly why
  their memo caches need no theme salt), and there is nothing to inherit from once the
  element is a file. The computed `color` is baked onto the root.
- **Paper.** A `<rect>` of the first opaque ancestor background — the "walk up for the paper
  colour" move `penrose_triangle` already makes — so a dark-mode save is not invisible in a
  white viewer. In Marp this resolves to the slide theme's own background, not white.
  ⚠ It takes the **viewBox rect**, never `width="100%" height="100%"`: mermaid's viewBox
  starts at `-8 -8`, and a 0-origin rect would leave the figure's own margin unpainted.
- **Fonts**, below.

**Font inlining is shared with the HTML export.** `__inlineFontFaceCss(families, urlFor)`
was lifted out of `buildExportArtifact()` and now serves both callers — the problem is
identical, so there is no second copy (CLAUDE.md #2).
- **tikz**: TikZJax emits `<text font-family="cmmi10">` pointing at Private-Use-Area
  codepoints, so without the matching Computer-Modern `@font-face` every label is blank tofu.
- **KaTeX in a `<foreignObject>`** (a feynmark `equation{}`): needs its *stylesheet* as well
  as its faces — the foreignObject markup is styled entirely by `katex.min.css`, which
  travels no better than the fonts do. `__katexInlineCss()` fetches it once, rebuilds only
  the `@font-face` rules for the families the figure's computed styles actually name (with
  the woff2 as a `data:` URI), drops the rest, and keeps the layout rules verbatim. Measured:
  a two-diagram feynman equation saves at ~190KB and renders identically standalone.
- Both are best-effort. A file that will not fetch costs that figure its glyph shapes, never
  the save.

**PNG.** A canvas block is `canvas.toDataURL('image/png')` — the readback path HTML export
already proves for both kataskeve3d and model3d, and model3d's 2× backing store means its
PNG is 2× the on-screen size, which is wanted. An SVG block is rasterized by handing the
serialized document to an `<img>` and drawing it into a canvas at **`__FIGURE_PNG_SS = 2`**;
⚠ a literal 2, not `devicePixelRatio`, for the reason `__MODEL3D_SS` carries — real DPR would
make the saved bytes depend on the reader's display scaling. The inlined `data:` faces do
resolve inside an `<img>`-rendered SVG (verified: the tikz PNG keeps its CM glyphs).
Plotly is the exception at every step and uses `Plotly.toImage()`, which owns the modebar,
the WebGL traces and its own colours.

**Host side.** `savefigure:` → `src/main.rs`; the payload is always **base64**, so one shape
carries the SVG text and the PNG bytes alike. Details, including why no watcher suppression
is needed, in `rust-host.md`. The result comes back as `FigureSaveDone` → a toast; unlike the
document exports it deliberately does **not** `open_with_default()`, since saving several
figures in a row would launch the image viewer each time. Cancelling the dialog posts
nothing, so the user gets no message for their own cancel.

**Exports need nothing.** `__createContextMenu()` appends its menu to `document.body`, and
both `buildExportArtifact()` and `--export-png` work from `#preview` — so there is no strip
pass, no `body.capturing` entry and no `@media print` rule, unlike `.abc-audio-bar`, which
needed all three precisely because it lives *inside* `#preview`. The DOM digest is unchanged
by this feature in all 12 `gate.sh` modes, which is the assertion to re-run if that ever
stops being true.
