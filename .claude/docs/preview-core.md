Markdown is rendered server-side to HTML via Rust's `pulldown-cmark` for the initial load and re-rendered client-side via `marked` for live updates. Both pipelines feed into `#preview` in `assets/index.html`.

**Shared webview-side helpers (`assets/index.html`).** The two pipelines and the many Marp pre/post-passes used to hand-roll the same scaffolding repeatedly; these are the single sources of truth, and a new feature should reuse them rather than add a sixth copy:

- **`__makeMdLineScanner(lines)` / `__rewriteMdLines(md, visit)`** — front-matter- and fence-aware line walking, previously written out **five** times inside `renderMarp()`. The scanner is a stateful single-forward-pass classifier returning `'fm' | 'fm-close' | 'fence' | 'code' | 'body'`; lines you skip are never examined, which is what the definition-list pre-pass relies on. `__rewriteMdLines` layers rewriting on top: `visit` is called only for `'body'` lines and may return `undefined` (copy), a `string`, a `string[]`, or `{ out, skip }` to consume a multi-line run. The slide→source-line map uses the classifier directly (it scans a different string and emits nothing). Regexes: `MD_FENCE_RE`, `MD_FM_DELIM_RE`, `SLIDE_SEP_RE`, `COL_DIVIDER_RE`.
- **`__isSentinelP(node, text)` / `__unwrapSentinelRegions(root, opts)`** — the "find an opening sentinel `<p>`, replace it with a wrapper, walk `nextSibling` to the closing sentinel, bucket at separators" shape shared by the inline-columns, alignment and definition-list post-passes. `opts` = `{ open, close, marker, wrap, fill }`; buckets always start with one `{ marker: null, nodes: [] }`. The **split** post-pass deliberately does *not* use it (no opening sentinel, stricter single-text-child predicate, rebuilds the section wholesale, header-hoisting tail) — forcing it in would be a worse abstraction.
- **Fenced-div grammar** — `ALIGN_KW_SRC` and the `ALIGN_*` / `COLS_*` / `FENCED_DIV_CLOSE_RE` constants built from it, plus `normalizeAlignKeyword()` (`centre` → `center`) and `alignKeywordClass()`. Add a keyword **here only**. `ALIGN_SENTINEL_RE` is separate on purpose: it matches an already-normalized sentinel, so it correctly has no `centre` branch.
- **Keyboard shortcuts** — `__isTypingTarget()`, `onPlainKey()`, `onCtrlKey()` (Ctrl/Cmd + letter, Shift excluded), `onShortcutKey()` (prelude only, for multi-key handlers) and `bindBodyClassToggle()` (restore + toggle + persist + toast). The text-entry guard was previously retyped 12 times. The listeners stay separate — their `preventDefault` placement and control flow differ.
- **`__createContextMenu()`** — floating right-click menu (`.app-context-menu` / `.app-menu-item`), owning the viewport clamp and the outside-click / Esc / scroll dismissal. Callers keep their own `contextmenu` listener and target test, so a right-click elsewhere still falls through to WebView2's native menu.
- **Lazy-library loading — `loadLib()` / `awaitLib()` / `__nextPaint()`.** `loadLib()` produces the cached per-URL `<script>` promise; **`awaitLib(ready, engine, els)` is the only sanctioned way to consume one.** It resolves `true`/`false` instead of throwing, and on failure paints a shared `.lib-error` box into every block that was waiting on that engine. **A figure branch must never `await` an `ensureX()` promise bare.** The reason is not tidiness: `loadLib()` rejects on a 404, so a bare `await` rejected `renderMarkdown()` itself, and `loadFileFromRust()` awaits *that* — so the lines revealing `#app-container` and calling `hideSplash()` were skipped and the app sat on the 「読み込み中…」 spinner **forever**, with the document invisible and nothing on screen or in the console (release builds have no devtools) to say why. A missing `assets/libs/feynmark/` in a built tree did exactly this to every document containing one `feynman` fence. A missing optional engine must cost you that engine's blocks, never the document. The tikz branches were written this way from the start and keep their own richer form (they distinguish *never installed* from *failed to load* via `__tikzUnavailableHtml()`, which `awaitLib` deliberately does not model). The error box is a single shared `.lib-error` rather than a sixth per-engine copy — the failure is about the loader, not the figure language, and mermaid has no error class of its own. `loadLib` caches **rejections** too, deliberately: every failure here is a permanently missing file under `assets/libs/`, and `#preview` is rebuilt on every ~150 ms live-edit keystroke, so evicting on error would spray hundreds of identical 404s into `md-previewer.log` for an outcome that cannot change. `loadFileFromRust()` additionally wraps its `renderMarkdown()` await in a `try/catch` that reveals the app, toasts, and calls `__emitRenderDone()` regardless — a last-resort net for the one case `awaitLib` cannot contain (`getMarp()` failing, where there are no slides to paint into) and for the `--export-png` host, which waits on `renderdone:` with no watchdog. **`__nextPaint()` replaces `await new Promise(r => requestAnimationFrame(r))`** in the Marp figure branches: rAF only fires while the window is painting, so in the hidden window `--export-png` renders into — and in a backgrounded tab — a bare rAF never runs and the await hangs the render forever, which is the same eternal-splash failure by a different route. It races rAF against a 50 ms timeout, so a painting window is unaffected. Regression net: hide `assets/libs/<engine>/` and load a document that uses it — the document must render with an error box, never a spinner.
- **Diagram memoization** — `__diagKey()` (theme salt), `__diagCacheSet()` (FIFO cap), `__diagSource(el, attr)` (percent-decoded `data-…-source` with a text fallback) and `__diagCacheHit(cache, key, el)`. There is deliberately **no** all-in-one render wrapper: markwhen cannot supply its cache key up front (the calendar key needs the parsed header's `country` and the month-count fallback), and mermaid caches the raw SVG string it was handed while abc must snapshot `el.innerHTML` after abcjs writes into the element.

**Diagram render memoization** — because `#preview` is rebuilt via `innerHTML` on every render (including every live-edit keystroke, ~150ms debounced), mermaid diagrams are memoized so an unchanged diagram re-attaches its prior output instead of re-running the (expensive) renderer. The shared module-level cache (`__mermaidCache` in `assets/index.html`) is keyed by `(dark/light theme salt + source string)` via `__diagKey()` — the renderer varies its output with `body.dark-mode`, so the theme salt is required for correct invalidation on the `M`-key toggle. The shared helper `renderMermaidCached` is wired into **both** `renderMarp()` and the normal `renderMarkdown()` async render phases. A FIFO cap (`__DIAGRAM_CACHE_MAX = 200`) bounds memory across long sessions; render errors are not cached. (Mermaid's optional `scale:` directive line is part of the cached source string, so changing the factor invalidates the entry — see *Mermaid*.) Plotly is excluded (live interactive widget). **ABC notation** (` ```abc `) is also memoized via `renderAbcCached` / `__abcCache` (wired into both pipelines), but with two differences from mermaid: (1) abcjs renders directly *into* the element (`ABCJS.renderAbc(el, src, …)` returns no HTML), so the helper snapshots `el.innerHTML` *after* rendering to populate the cache; (2) the key is the **raw source with no theme salt** — abcjs output is monochrome SVG recolored for dark mode purely via CSS, so the rendered bytes don't vary by theme and the cache stays valid across the `M`-key toggle. **Markwhen timelines** (` ```markwhen `) are memoized via `renderMarkwhenCached` / `__markwhenCache` (wired into both pipelines), keyed by `__diagKey(src)` **with the theme salt** like mermaid — the renderer bakes concrete light/dark colors into the SVG (the `::highlight`-style `var()` non-inheritance into generated SVG strings makes baked colors the simplest correct choice), so the salt invalidates the entry on the `M`-key toggle. The markwhen **calendar view** (`display: calendar`) uses a *separate* `__markwhenCalCache` whose key additionally carries the holiday country and online/offline state (`|cal|<country>|on|off`), so switching connectivity re-renders with/without holidays — see *Preview Pipeline → Markwhen timelines → Calendar view*. **tikz / tikz-cd** (` ```tikz ` / ` ```tikzcd `) are memoized via `renderTikzCached` / `__tikzCache`, keyed by `kind+source` with **no theme salt** (like abc — the SVG is `currentColor`, recolored for dark mode by CSS) — see *Preview Pipeline → tikz-cd commutative diagrams*. **Kataskeve 2D** (` ```kataskeve `) is memoized via `renderKataskeveCached` / `__kataskeveCache`, keyed by `__diagKey(src)` **with the theme salt** — almost the whole SVG is `currentColor`, but the optional grid and axis colors are baked and the engine picks them from `body.dark-mode` (this app's own convention), so without the salt the `M` key would leave a stale grid color behind. **Kataskeve3D** (` ```kataskeve3d `) is the one renderer with **NO entry in this scheme at all**, and `__diagCacheHit` must never be used for it: it rasterizes to a `<canvas>`, whose *bitmap* is not part of its serialization, so `el.innerHTML` round-trips to an empty `<canvas>` tag and re-inserting it yields a **blank** canvas — and because `__diagCacheHit` returns `true` on a hit and the caller returns, every 3D block would be a permanently empty box from the second render on. The library solves it at the right layer instead: a module-level LRU of 64 offscreen bitmaps keyed by `(hash(source), ink colour)` that blits the stored bitmap onto the fresh canvas. That cache lives **outside `#preview`**, so it survives the `innerHTML` rebuild that discards ours (exactly what the 150ms live-edit path needs), and keying on the ink colour makes it theme-salted for free. `renderKataskeve3dBlocks` is therefore named `…Blocks`, not `…Cached`. Memory: ~`w*h*4` per entry (~1.25MB at the 680×460 default, ~80MB saturated); the only flush lever is `Kataskeve3D._debug.clearRenderCache()`, deliberately not wired up. **Feynman diagrams** (` ```feynman `) are memoized via `renderFeynmarkCached` / `__feynmarkCache`, keyed by the **raw source with no theme salt** (like abc/tikz — feynmark renders `stroke/fill: currentColor`) — see *Preview Pipeline → Feynman diagrams*.

**Marp instance reuse** — `renderMarp()` builds its `Marp` instance once via `getMarp()` (cached in `__marpInstance`) and registers theme CSS once, instead of `new Marp()` + re-`themeSet.add()` on every render; `marp.render` is effectively pure and `themeSet.add` is idempotent, and theme switching works by rewriting the front-matter `theme:` line against the already-registered theme set.

- **`data-line` fidelity (a precondition for anything that splices source)** — `data-line` is meant to be a faithful 1-based line number into the LF-normalized source, and every preprocessing pass in `renderMarkdown()` must therefore preserve the line count. Two passes did not, and their errors compounded: `extractMathInto()` padded a masked fenced block with `'\n'.repeat(n)` *and* restored the fence verbatim at the end, so every code block inflated the count by (fence lines − 1); and `extractFootnoteDefinitions()` deleted definition lines outright. Together they made `data-line` wrong by tens of lines in ordinary documents — `samples/sample.md` (153 lines) stamped a heading as `data-line=176` — silently breaking editor↔preview scroll sync and the `jumpto:` reverse jump, and making any `data-line`-keyed source splice unsafe. Both are fixed (the fence placeholder needs **no** padding precisely because it is restored verbatim), and `data-line` now matches real source lines exactly. **If you add a preprocessing pass, it must be line-count preserving**; the regression net is `tools/preview-harness/domdump.py` (the digest records `data-line` per block, so any drift shows up as a diff).

- **Zoom shortcuts**: `Ctrl++`, `Ctrl+-`, `Ctrl+0`.

- **Help modal** (`H` key) — toggles a modal listing every keyboard shortcut. Closed by `H` again, `Esc`, the × button, or clicking the backdrop. Pure webview-side feature in `assets/index.html`; no Rust changes. **Every visible string is localized (ja / en)** — the modal (title, all 20 shortcut rows, footer link, close `aria-label`), the style/Marp-theme picker, `showToast()` messages, the splash, the drop-zone text and the TOC toggle tooltip all go through `t()` or a `data-i18n` attribute; see *UI Language*. Internal keys (localStorage values, CSS class names like `deck`/`scroll`/`list`) are unchanged — only display text is localized. The footer also carries the **language picker** (`自動 / 日本語 / English`). The modal also has a **Third-party licenses** link that fetches and shows `assets/THIRD_PARTY_LICENSES.txt` in a `<pre>` pane. Its footer also shows the **app version** (`v<X.Y.Z>`): the Rust host injects `window.__appVersion` (from `env!("CARGO_PKG_VERSION")` = `Cargo.toml`'s `version`, so it auto-tracks the release-automation bump) alongside `__userStyles` / `__marpThemes` in `src/main.rs`, and `setHelpOpen()` writes it into `#app-version` when the modal opens.
